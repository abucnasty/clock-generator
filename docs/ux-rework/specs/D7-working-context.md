### New API and persisted shape (provider first)
`type BuildViewContext = { version: 1; view: 'configure'|'results'; configView: 'list'|'diagram'; resultDetail: ResultDetail; detailsTab: 'insights'|'fuel'|'blueprint'; sections: Record<string, boolean>; comparison: { allColumns: boolean; showUnstable: boolean }; wakeAsTable: boolean; entity: { kind: EntityClickType; id: number; signature: string } | null; entityConfigKey: string | null; position: Partial<Record<'configure'|'results', { anchor: string; offset: number }>> }`.
`contextKeyOf(buildId: string): string` uses dedicated `clock-generator-view-context:<id>`; safe `readBuildViewContext(storage, buildId)` / `writeBuildViewContext(storage, buildId, value)` / `removeBuildViewContext(storage, buildId)`; `useBuildViewContext({ buildId, ready, ...validated ownership seams })` returns context+patch and restore scheduling; exact callback readiness contract finalized against completed D1 state owners before coding. Persist only bounded known section/anchor IDs, finite clamped offsets and validated enums, never arbitrary DOM selectors. No result cache, build export or D6 fields.

## Acceptance criteria
- [ ] First inventory actual losses: Configure/Results stay mounted (`App:962`) and already retain in-session expansion; selection/cache restore exists. Extend missing reload/per-build context only, and list each stored field's real owner/control. Do not add sort/filter controls absent from product; persist allColumns/showUnstable and actual existing timeline filter choices only if present and relevant, with enum/ID validation.
- [ ] Context keyed by `library.currentId`, not Config key: two named builds can share identical data yet different navigation. Hydrate only after correct library ID/form and result restoration readiness; no transient default writes overwrite saved context before hydration. Missing/invalid/future-version/blocked storage falls back to working default safely.
- [ ] Selected live entity may use UUID while mounted. For reload persist kind + numeric id + canonical signature **and** saved `serializeConfig(form)` identity (UUID-free); restore only when saved build identity/config and current entity signature agree. `_uuid` is stripped and regenerated: bare UUID never promised across reload. Structural change/renumber ambiguity clears selection instead of selecting unrelated new occupant of old numeric ID. No stable-ID/schema project or signature guessing.
- [ ] Context lifecycle: switch saves departing view and restores destination; New/share-as-new starts default; Duplicate starts default context rather than copying source offsets/draft; Rename retains context; Delete removes only that build's context; full Reset/import/whole-build replacement invalidates entity/position and returns sensible Configure while retaining browser Display; Undo restore may recover entity only if original stored identity matches again, otherwise safe no selection. Edits not replacing structure preserve valid view/sections and validate relevant entity on next restore.
- [ ] Cross-tab navigation changes do not hijack active tab's view/scroll or cause build-conflict alerts; read latest validated context on next open/reload. Actual other-tab build reload invalidates identity-dependent entity/offset, preserves current build-conflict decision flow. No automatic overwrite of form or unsaved draft.
- [ ] Results view restores only if usable restored result exists; otherwise Configure with existing status. Missing fuel tab falls back to insights; removed result/section anchors fall back to containing heading. D1A Install action must show full current applicable guide even if older global collapse flag was set. No duplicate persistence owners fight over that state.
- [ ] Position stores nearest known section/view anchor plus finite offset. Restore once after layout/library/cache settles and account for actual sticky header; clamp after responsive/theme/density layout changes. Never focus field/open dialog as a side effect of scroll restoration. Native scroll/key/pointer activity after open, Generate, Copy action navigation or validation/problem jump cancels pending restoration; no late jump overriding player action. Do not promise pixel-exact location across different widths.
- [ ] Save/Cancel and draft confirmations unchanged. Restoring selected entity shows selection/context without reopening an editor containing a fabricated unsaved draft; deliberate open uses saved form. Reload loses unfinished dialog edits as before. Chosen clock/cached stale warnings/Undo remain unchanged.
