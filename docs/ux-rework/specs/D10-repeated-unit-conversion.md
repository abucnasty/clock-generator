# D10 — Convert repeated identical units automatically

Status: owner-requested Phase4 feature intent,2026-10-16. Detailed implementation spec/API and evidence fixtures must be finalized against the accepted integrated engine. Not implemented. This request supersedes PLAN's earlier manual-selection-only/no-conversion restriction for repeated units; it does not approve the pending upstream audit wholesale or reopen other unapproved feature proposals.

## Player outcome
- A repeated-unit refusal offers a concise recovery: “8 identical units found. Use one unit with8 copies.” Action: “Use one unit ·8 copies”. The original selection is unchanged until the player accepts.
- The application extracts one complete representative modeled unit and computes Copies. The player enters only the final TOTAL production rate in the existing target field; they do not reselect in Factorio, edit Copies, divide the rate or manually delete duplicate entities.
- Preserve any already-entered total target. For an input with existing Copies, use exact engine arithmetic: configured Copies × detected multiplicity. Preserve fractional Copies and normal validation;8 found with existing1 becomes8, while existing0.5 becomes4. Do not silently round or reset the existing multiplier.
- Commit conversion atomically, announce the result and offer existing whole-build Undo. Restore the exact original config and applicable result/manual-choice snapshot on Undo. Recheck automatically after conversion while retaining Undo; focus the total-rate field if further entry is needed. Use the internal validation path rather than an explicit Check/Generate handler that withdraws Undo. No compulsory wizard, automatic Generate or new acknowledgment sequence.

## Correctness boundary
- Use a canonical engine-backed normalization/proof, not prose parsing or a second approximate grouping algorithm in the UI. The current refusal detector is evidence of repeated structure, not permission to discard arbitrary entities. Its structured result currently identifies machines; complete entity membership/reference rewriting and stronger equivalence checks are implementation prerequisites.
- Retain the correct representative of every component kind in a composite unit, not merely the first machine. Include its inserters, machines, buffer chests, drills/targets and necessary external belt/infinity-supply references. Preserve ordered filters, rules, machine fuel, timing metadata, nearest-lane information and overrides and, after0.16 compatibility, consequential drop/order semantics. Retain original retained-array order/IDs and applicable UI identity; do not use a sequence of destructive row deletions or unconditional renumbering. Close any existing config-to-form metadata loss before relying on that mapping for conversion. Preserve endpoint and configuration references without dangling IDs or accidental changes to effective behavior.
- Shared resources, heterogeneous units, ambiguous membership or unproven coupled lane/drop/order behavior must not be silently reduced. Offer automatic conversion only when the engine can construct and validate a supported representative config. Otherwise keep the input intact and retain the manual select-one-unit recovery with a useful reason. No new geometry authoring/export or simulator policy is included.
- Worker validation/generation must carry typed structured recovery information, bound to the exact checked build/request. Never derive a conversion from the error text or apply a stale recovery action to a subsequently edited/switched build. Revalidate the candidate through normal schema/planning checks; the conversion does not certify that a target or clock is achievable.
- Preserve live/draft editor semantics and normal stale-result/copy consent. An explicit conversion may replace the build snapshot; it must not reinterpret previous clocks as freshly valid results.
