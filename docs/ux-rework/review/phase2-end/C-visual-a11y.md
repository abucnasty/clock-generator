### 1. Gut reaction

I can now see what the tool is for and where to start. The green Paste button, neutral first-step instruction and coherent Build card give the screen a hierarchy that the original lacked. Results finally leads with an answer: production, wake-ups, recovery, belt assumption and Copy are legible before I reach any chart. I still encounter too much instructional material before the visual evidence, and some of that material now contradicts the underlying counting model. The remaining accessibility weakness is concentrated in secondary player-facing surfaces rather than spread across every control.

### 2. Top 5 changes I’d make tomorrow

1. **Make failed Copy visible and recoverable.** Every Copy blueprint action uses a hook whose failure path only writes to the console. Show and announce “Couldn’t copy the blueprint,” then offer a selectable string or take focus to Blueprint string. A browser restriction should not make the product’s main action appear silent.

2. **Give Fuel an equivalent to its hover-only event detail.** The summary and consumption tables are useful, but neither supplies the actual swing intervals and quantities available by hovering the timeline. Add a small “Show events as table” disclosure with inserter, start, end and items, and a meaningful text summary of the fuel trace. Fuel is in normal Details, so the developer-timeline exception does not cover it.

3. **Use one current definition of a wake-up.** Wake windows and the expanded comparison-table help still say a machine “finished a craft.” Terms correctly distinguishes craft starts for inputs from finishes and productivity payouts for outputs. Feed both help locations from the same current definition so the chart explains the number it actually displays.

4. **Correct the output-swing unit before polishing more pixels.** Advanced says “Per output inserter, per crafting cycle,” while its note says the forced count is divided between output inserters. The check result also says “Each output inserter makes N swings” for an engine value summed across the first output machine’s output inserters. Label that total and explain the split consistently.

5. **Show what a paste will replace.** “Machines (1)” tells me how much came from Factorio, not what I lose. Add current → imported counts and a reference warning when selected inserters depend on unticked entity types. Append can stay a separate follow-up; a truthful replacement preview is the immediate improvement.
