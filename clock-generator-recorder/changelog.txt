Version: 0.11.1
Date: 2026-11-18
  Bugfixes:
    - A staged start counts a lane that only the inserters of the cell fill as saturated (no loader, built inserter or mining drill feeds its belt), so a build whose belt the cell alone fills is not refused
    - A staged start wires the clock to each of several mining drills: the drills of the trial build are matched to the config's by where they stand, and the mod finds them in the build that is made again (clock.drill_positions); a build with one drill is wired as before
    - A backpressure start records settle_ticks ticks after the lock opens, as a staged start without the fill does
  Features:
    - The description of a build lists its mining drills with their positions (movers.drills)

Version: 0.11.0
Date: 2026-11-17
  Features:
    - A staged start can ask for the backpressure start (staged.backpressure): the inserters of the cell are built and the clock is wired with its Clock lock on, the build fills until every crafting machine finished as many products in two windows in a row (or a cap), and then the lock is set off and the recording starts in that tick; the kick start of loops, the seeds and the probe go in at that tick. The status reports the fill (fill: phase, the opening with each machine and inserter of the cell, the counter after the opening)

Date: 2026-11-10

Version: 0.6.0
Date: 2026-10-08
  Features:
    - harness_clear removes the build the harness made, with the clock wired to it and the items it left on the ground, so one game can record several builds one after another
    - A recording names the lane nearest to each inserter that picks up from a straight piece of belt (near_lane on its source), so a config that has the inserter take the other item first is told apart from the build
  Changes:
    - harness_build leaves the game's speed as it is when the job names none; it used to set it to 1
    - The harness removes a build's constant combinators with its clock, since a generated clock now has a lock switch, a constant combinator wired to it
    - harness_describe also lists every inserter and loader of the build with the entity at each end, so the harness can refuse a build that holds one the config does not describe
    - Belt pieces joined to each other, through undergrounds and splitters as well, are described as one belt, with lanes read from all of its pieces. A lane that had run dry under one inserter used to split a belt in two, and an inserter over an empty piece was put on the first belt
