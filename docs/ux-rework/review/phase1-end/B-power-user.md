# UX review B: power-user interaction designer, end of Phase 1 (0.9.0 + Phase 1, commit 84197ba)

Screenshot paths are relative to `/tmp/ux-capture/out/phase1-end/`. When no folder is given, the shot is in `w1440/`. Source paths are relative to `/tmp/ux-review-p1/clock-generator-ui/src/`.

### 1. Gut reaction

This is a different tool from the one I reviewed. It no longer hands me a blueprint for the wrong build. Deletes and imports can be undone. "Inserter 3" means the same inserter in the row, the diagram, Insights and the timelines. The disabled buttons tell me what is wrong and take me there. The safety net is too eager, though. "Build imported. Undo" sits over the middle of my work through Validate, Generate and every view switch. While it is up, Ctrl+Z on any non-text control quietly reverts the whole import (09, 34, 35). The iteration loop is still slow. Validate is a separate step, it drags me to the bottom of Configure, and every edit locks Generate until I validate again. Dragging a row silently renumbers every inserter after it. I now trust what I'm shown, but I'm still clicking too much to get there.

### 2. Top 5 changes I'd make tomorrow

1. **End the Undo offer when I commit, and get the message off the work surface.** The offer only ends on an edit, Close, Esc or opening an editing dialog (`hooks/useUndo.ts:44-50`). So "Build imported. Undo" survives Validate, Generate and view switches. It sits top-centre right under the header, on top of whatever row or table cell is there: the Destination field in 09, the clock table's Output swings column in 34, the Target Output heading at 390 (`w390/06`). For as long as it shows, Ctrl+Z on a clock radio or a button reverts the entire import (`useUndo.ts:170-177`). The change: withdraw the offer when Validate or Generate starts, since running the build means I've accepted it. Anchor messages bottom-left from 960px up. That is not a timer, so it stays within the owner's WCAG 2.2.1 decision. Today a stray Ctrl+Z ten minutes after an import can throw away the build I've been generating against.
2. **Merge Validate into Generate (carried B10; per PROGRESS.md it is already merged as 2.3 on p2).** On this build Validate still switches to Configure and scrolls to the Validation panel (`App.tsx:258-267`). Any edit still turns Generate off (`WorkflowBar.tsx:233`, `validationStatus !== 'valid'`), and the Search deeper button with it (`App.tsx:411`). Every tweak costs an extra click plus a jump in where I am on the page. This is still the biggest tax on my loop. If 2.3 lands as specified, it's done.
3. **Make the stale banner say what changed and do the next step.** "These clocks are for logistic-science-pack at 240/s. Your build has changed since. Generate again." (28, `utils/resultsStaleness.ts:57-59`) names only the recipe and rate. Change a stack size and the banner describes a build that reads exactly like the one I have now. It also says "Generate again" while Generate is disabled until I validate. Change it to: "Generated at 14:02. Changed since: Inserter 2 stack size 16 → 12, Items per second 240 → 200." Add a **[Validate and generate]** button in the banner. The diff is cheap: both keys are JSON of the config.
4. **Announce and undo reorders.** Deleting a row says "Deleted Inserter 2. Inserter 3 is now 2." and offers Undo (`utils/undoSnapshot.ts:128-170`). Dragging a row renumbers every entity of that kind (`utils/configForm/edits.ts:519-543`), with no message and no Undo (`App.tsx:542-608` passes `reorder*` straight through; only removes are wrapped in `undoable`). Last run's "Inserter 5" is now a different row, and nothing tells me. Wrap reorders like removes: "Moved Inserter 5 to 2. Inserters 2–4 are now 3–5. Undo".
5. **Make the clock table a decision table, not a page.** The intro is one line now and the unstable rows are grouped (26, 28). That is real progress. But the table, its reason line, the disclosure and the Search deeper notice still fill the 1440×900 viewport, and the tabs start below it (19 part1). No column sorts. When the stable "2 output swings per cycle" with **0** wake-ups loses to a 177 pick, the only explanation is "…on a moving belt" in the lead sentence. Add sortable headers, a short "Why not" cell on non-picked rows ("non-moving belt", "+7 wake-ups", "no recovery"), and a "Collapse to selected" toggle that keeps the tabs in view.

### 4. What I'd cut or hide

- **"Debug Output" on the empty Results page and as a peer tab.** Move it behind Developer tools (2.5).
- **The three-line Validation paragraph and the Exclude from LCM chips** on the default path (10 part2, 30 part2). Move them to Advanced (2.3 says so).
- **The footnote under "Always search deeper for this build"** ("With Search deeper, also turns on…"). Put it in the checkbox's tooltip.
- **The Fullscreen button on the rule dialog** (11). Size the dialog properly instead.
- **The diagram as a second editor.** Its dialogs don't share the List's commit model (#5).

### 5. What already works

- **The removal message is exactly what a power user needs.** "Deleted Machine 2. Machines 3–4 are now 2–3. Inserters 1–2 have no Source now." plus Undo (`utils/undoSnapshot.ts:128-170`).
- **The stale guard is airtight.** Import, Paste and Reset clear results (32). An edit gives "Copy old clock…" with a confirm (28, 29). The Blueprint tab hides the string (`resultsStaleness.ts:11`).
- **The recommendation explains ties.** For example: "1 other clock for a moving belt ties on wake-ups, so the one with fewer wake windows was picked" (34 part1). The chip stays on the recommended row, and "Back to recommended" appears when you select another row (`ClockAlternativesPanel.tsx:145-151,199-209`).

### 7. Open questions for the author

1. Should Undo survive a Generate? I'd say no, because once you've run the build you've accepted it. That one decision fixes #1.
2. Is drag reorder worth keeping now that it renumbers everything? If order means nothing to the engine, removing it removes #4.
3. The checkout is `0.9.0` (`clock-generator-ui/package.json`, `clock-generator/package.json`, no 0.9.1 in `CHANGELOG.md`), but this round was described as 0.9.1 + Phase 1. Is master's 0.9.1 engine fix meant to be in what was captured?
4. Should a target above what the machines can make block Validate, or only warn? That decides where #7's check lives.
5. In the diagram, should the dialogs be drafts (Save) or live (Undo)? Either is fine; mixing them isn't (#5).
