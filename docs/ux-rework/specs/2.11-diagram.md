## Change

What the player sees and does differently:

- **Arrowheads on every edge**, so the flow reads source, inserter, destination. The arrow stays the colour of its edge
  when the edge is highlighted on hover.
- **The layout runs left to right: sources, then the machine, then the outputs.** Today a belt (or chest) that feeds a
  machine and also takes its output makes a loop for the layout. The layout breaks the loop by turning one inserter
  around, so the input inserters of `logistic-science.json` end up to the right of the machine, with their edges
  looping back (C20, B16). The fix: **a belt or chest that is on such a loop is drawn as two nodes, "Belt 1 (in)" on the
  left (what feeds the machines) and "Belt 1 (out)" on the right (what takes their output).** Both stand for the same
  belt: clicking either opens the one belt dialog. A belt that only feeds, only receives, or sits in a chain
  (machine to belt to machine) stays one node. Drills stay on the left, as sources. The loop of machines that feed
  each other (the existing `loopInserterIds` case, e.g. two biochambers) keeps its vertical placement.
- **All text in the Diagram is at least 12px**, and the machine node's footnote ("5.2t craft · insertion limit ×15", from 1.10) uses the
  secondary text colour instead of `#666` (2.74:1 on `#232323`, fails 1.4.3). Nodes grow to fit and the layout's node
  sizes grow with them, so nothing overlaps or is clipped.
- **A node chip says the same thing as the List row's chip** (the 1.13 follow-up). An inserter with a rule shows
  e.g. "Enable: Clocked 0–7 of 192", not "CLOCKED". The Overrides tab's chip in the inserter dialog does too.
- **Fullscreen fits the view.** Opening the fullscreen Diagram fits the whole graph in the canvas, which is the full
  window below the title bar (today most of the canvas is empty).
- **Enter on a focused node opens its dialog**, as a click does. Focus returns to the node when the dialog closes. A
  focused node shows a visible ring (React Flow's own CSS removes the outline, `style.css:449-451`).
- **The belt lane ("Nearest lane of the belt", `near_lane`) can be set in the List too** (B17). A List row whose
  source is a belt with two different items on its lanes shows the same select the Diagram dialog has, with the
  same label and options. Both views share one component, so they cannot drift again.

Not in this item (and why): the Diagram's `Assembler` label goes with 1.12 (Part A, "Assembling machine"); `#N` labels and the
current numbers go with 1.9; "Show rates" toggle naming is C16/1.11; draggable nodes and saved positions (B16's
other half) stay out, the Diagram is secondary; B7's "Show only overridden" List filter is not built here (carry to 3.2).

## Risks and checkpoints

- **No checkpoint is tripped**: no new dependency (`MarkerType` and `useReactFlow` are in the installed `@xyflow/react` 12.10.2), no engine, mod or CI change, no change to an owner decision. The Stack Size fallback line in file 10 and the split-node design are the two calls for the orchestrator to confirm.
- **Shared files.** `buildFlowGraph.ts`, `InserterFlowNode.tsx` and `DrillFlowNode.tsx` are also edited by **1.9** (labels via `entityLabel`, `Inserter #N` becomes `Inserter N`), `EntityFlowNode.tsx` by **1.12 Part B** (the "insertion limit" copy), `ConfigFlowDiagram.tsx` by **1.8, 1.3, 1.14** (colours at `:138,287-291`) and **1.11** (the fullscreen dialog's `aria-labelledby` in `App.tsx`), `InserterConfigPanel.tsx` by **1.8** (draft/Save), and the node colours by **2.7** (Factorio GUI grammar) and the recipe names by **2.8** (in-game names). Work the changes to different hunks; merge the phase branch before reporting and before the PR.
- **Node ids change for split entities** (`belt-1` becomes `belt-1-in` / `belt-1-out`). Nothing outside `buildFlowGraph.ts` parses node ids (checked: a search of `src` for `flowNodeId` and `'belt-` finds only the graph builder), but the capture scripts that select by `.react-flow__node` text are unaffected, and `capture-numbers.mjs` finds the machine by "/s out". If the id scheme changes at 1.9, only `flowNodeId` is touched.
- **Hover on one half** highlights only that half's edges (the highlight works on node ids). That is acceptable: the other half's side is not what you are pointing at.
- **The 12px floor is CSS px.** `fitView` scales the whole graph, so a large build (`low-density-structure.json`, 15 inserters) fits at a zoom below 1 and the text on screen is smaller than 12px. That is the nature of a fit-to-view map; the Controls' zoom and the fullscreen view give the room. Do not set a `minZoom` that hides parts of a big graph. Say so in the evidence note.
- **Stale `near_lane`.** If a belt's lanes change so its source no longer shows the select (same item on both lanes), a saved `near_lane` stays in the config unseen. It is harmless to the engine (`nearestLaneFirst` ignores a lane whose item is not in the set) but invisible. Left as a follow-up, not fixed here.
- **React Flow's `nodesFocusable`** is on by default and the nodes are `role="group"`; adding `ariaLabel` makes screen readers read the label. The edge elements remain unnamed (out of scope; edges are decoration for the keyboard, nodes carry the content).
- **Dialog focus restore** relies on MUI returning focus to the node that was focused when the dialog opened. If a dialog opened by a click has no focus to restore, nothing breaks; the capture checks the Enter case only.
- **A drill node has no target handle and a belt-half has one handle fewer**: connecting by dragging to the wrong half is blocked by hiding the unused handle. If hiding a handle breaks React Flow's connection rules in the shots, fall back to leaving both handles and keep the rest.
