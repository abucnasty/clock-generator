# 2.9 Half-width layout
Findings: C14  ·  Implementer model: sonnet  ·  Branch: feat/ux-rework-p2-half-width

Owner decision this serves ("Widths"): full support for desktop and half-width down to 720px. Below 720px only
Configure, Results and the main actions (Generate, Copy) have to stay reachable, and that guarantee is 1.2's. WCAG
1.4.10 Reflow at 320px conflicts with that decision and is **not built** (1.11's note, for the Phase 2 retro). Nothing
below 720px is a target, and no acceptance criterion below tests it.

**Size: this touches 14 files (11 product files, 3 of them new; 3 under `docs/`).** That is over the "about 5 files"
line in `ORCHESTRATOR.md`, which says to move such an item to `opus`. The edits are small and repetitive (one wrapper
component used at ten places), so `sonnet` is the recommendation, but the orchestrator decides. See "Risks and
checkpoints" for the ordering problem, which matters more than the model.

`playwright-core` and the `lib.mjs` helpers, on three samples: `science/logistic-science` (3 inserters, results

The review (C14) only has 390px shots, so these are the first 720 to 960 evidence.

minimum width and scroll inside their own container below it, so nothing can be squeezed to a sliver at any width, and
(3) stop the workflow bar wrapping at 720. Plus (4) a geometry check in the capture that keeps all of this true as
later items add views.

## Change

- **A shared scroll container.** One small component, `ScrollX`, holds anything wider than the window: it scrolls
  sideways inside itself, never moves the page, can be reached by keyboard, and fades the edge that has more content so
  the player can see it scrolls.
- **The Potential Clocks table keeps its Clock column readable.** The Clock column is at least 200px wide, the other
  cells stay on one line, and the table scrolls inside its box with a visible fade at the right edge. At 720px the
  player sees the radio, the name and the Belt column, and can scroll to Wake-ups, Rate, Output and Status.
- **The Fuel tab's two tables do the same** (cells on one line, scroll inside the box). Insights tables get the same
  scroll box, without changing how their cells wrap.
- **Timelines and the other charts have a floor.** Each chart, with its time axis, is at least 560px wide (a 200px
  label column and a 360px plot). In a box narrower than that it scrolls sideways inside the chart's own container; the
  legend and the controls above it stay put and wrap. At 720px and wider nothing changes.
- **The workflow bar stays within two rows at 720px.** The selected-clock label (`3 output swings per cycle`) hides
  below 900px instead of 600px; the table already shows the selected row. The toggle, Copy blueprint, Valid, Validate
  and Generate remain.
- **Forms, dialogs and the diagram are left alone.** Measured above: they reflow and never overflow.
- **The capture gains a geometry check** (no sideways page scroll, nothing sticking out of the window, the named
  containers scroll, the header stays clickable) that runs at 960, 800 and 720 on every view the capture reaches, so each
  later item can run it.

1. `components/ScrollX.tsx` (new, about 45 lines).
   - Props: `label: string` (its accessible name), `minWidth?: number | string`, `children`, `sx?`.
   - Renders `<Box role="region" aria-label={label} tabIndex={0} sx={{ overflowX: 'auto', maxWidth: '100%', maskImage, ... }}>`
     with an inner `<Box sx={{ minWidth }}>` holding the children. `tabIndex={0}` lets a keyboard user scroll it
     (axe `scrollable-region-focusable`); the focus style is the global ring from 1.11, with `outlineOffset: -2px` on
     `:focus-visible` so the ring is not cut by the mask.
   - Keeps `{ start: boolean; end: boolean }` in state (is there more content before, after). Updates it from the box's
     `scroll` event and from a `ResizeObserver` on the box and the inner element (a table gets wider when rows come in).
     Sets `maskImage` and `WebkitMaskImage` to `edgeMask(start, end)` (below). No overlay element: the fade is a mask, so
     there is no colour to match against the Paper's dark-mode elevation tint.
   - Style: match the other components (named export, 4-space indent, single quotes, semicolons).
2. `utils/scrollEdges.ts` (new, about 25 lines), pure so it can be tested:
   - `scrollEdges(scrollLeft: number, clientWidth: number, scrollWidth: number): { start: boolean; end: boolean }`:
     `start = scrollLeft > 1`, `end = scrollLeft + clientWidth < scrollWidth - 1` (the 1px slack absorbs subpixel
     rounding).
   - `edgeMask(edges: { start: boolean; end: boolean }): string | undefined`: `undefined` when neither is true;
     otherwise `linear-gradient(to right, <transparent|black> 0, black 24px, black calc(100% - 24px), <black|transparent> 100%)`,

    - `geometry(page)`: returns `{ pass, sideways, offscreen, detail }`. `sideways` is `noSideScroll`'s test.
      `offscreen` lists visible elements whose rect has `right > innerWidth + 1` or `left < -1`, skipping any element that has
      an ancestor with `overflow-x` other than `visible` whose own rect is inside the window (a scroll box clips them).
      Skip zero-size elements and `visibility: hidden`. A short description per offender (tag, a Mui class, the first 40
      characters of its text, left and right) makes the FAIL line readable; cap the list at 8.

      returns `{ found, overflowX, clientWidth, scrollWidth, right, scrolls, tabbable }`, where `scrolls` is
      `scrollWidth > clientWidth + 1`, `tabbable` is `tabIndex === 0` and `overflowX` is the computed value.

  is `{ start: true, end: false }`.

- `edgeMask({ start: false, end: false })` is `undefined`.

  and ends with `transparent 100%)`; `{ start: true, end: false }` the mirror; both gives a fade on each side.

## Risks and checkpoints

- **No checkpoint trips:** no new dependency, no CI or settings change, nothing the plan does not cover. WCAG 1.4.10 at
  320px stays out, as the owner decided; it goes into the Phase 2 retro as already noted by 1.11.
- **Ordering is the real risk.** This item is "every view works at 960, 800 and 720", but Phase 2 still builds views and
  rewrites layouts: 2.1 (first visit), 2.3 (removes Validate from the workflow bar), 2.5 (Results lead with the answer),
  2.6 (Wake windows view, new), 2.7 (GUI reskin: title-bar panel headers, new paddings, colours on every table), 2.10
  and 2.11 (timelines, diagram). If 2.9 merges before them, "done" is true for a layout that is then replaced.
  **Recommendation: merge 2.9 after 2.1 to 2.7 and ahead of 2.10 and 2.11** (the plan's order already puts it after
  2.7), and make `capture-half-width.mjs`'s geometry sweep a standing gate for the items that add a view (2.6, 2.10,
  2.11): each runs it at 960, 800 and 720 on its own view, and the phase-end review re-runs it. I would also hold the
  spec's line numbers and table-column assumptions until 1.6, 1.7 and 1.10 are merged; this spec says "find it by the
  text" for that reason.
- **Shared files, expect merge conflicts.** `ClockAlternativesPanel.tsx` (1.6 restructures the rows, 1.7 changes the
  "Not searched" alert, 1.10 changed the headers, 2.7 restyles), `WorkflowBar.tsx` (1.1, 1.2, 1.4, 1.14, 2.3),
  `StateTransitionTimeline.tsx` and `FuelPanel.tsx` (2.10 recolours and adds a legend, 3.x), `lib.mjs` (every item).
  Per the orchestrator's rule: merge the phase branch into the branch before reporting and before the PR, and read the
  conflicted hunks. The wrappers here are insertions around blocks, so conflicts should be about indentation.
- **The mask fade is new behaviour.** `mask-image` hides the content it fades, so a focus ring or a tooltip arrow
  that sits at an edge may be dimmed: the focus ring is inset (`outlineOffset: -2px`), and the MUI `Tooltip` renders in
  a portal, so it is not masked. Check the radio of the first row and the Status chip's tooltip at 720 in the shots.
- **`tabIndex={0}` regions add tab stops** (one per region, 2 to 5 on a Results page). That is the accepted cost of a
  keyboard-scrollable region and what axe asks for; 1.11's axe pass should be re-run on Results at 720 (one `region`
  per name, no `scrollable-region-focusable`, no `landmark-unique` complaint: if axe objects to the repeated role,
  drop `role="region"` and keep `aria-label` with `role="group"`).
- **Sticky header height** at 720 is about 120 to 190px of a 900px window (app bar, workflow bar, sticky footer is
  another 50). Not changed here beyond the one-row goal; the footer is 1.5's.
- **`opus` or `sonnet`.** The orchestrator's "over 5 files" rule would move this to `opus`. The change is mechanical and
  the acceptance criteria are measurable, so I'd keep `sonnet` and let the code review (opus) carry the risk; the
  orchestrator should decide.
- **Not in this item (follow-ups if wanted):** cards instead of a table for the clocks below 600px (C14's proposal; phone
  widths are out of scope); a narrower 96px timeline label column; wrapping the lane Stack Size field under Ingredient
  (only collapses at about 390px); the sticky footer at phone widths (1.5); tiny diagram node text (2.11); the timeline
  zoom (3.x).
