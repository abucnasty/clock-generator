## Owner checkpoint: the install and wiring steps (derived from the code)

**For the owner to review before PR A merges, and to try in Factorio 2.1** (`PLAN.md` Phase 2 done-when and Verification 3).
The steps are shown to newcomers verbatim, from named constants in `utils/installSteps.ts`, so a wording change is one edit.
Each step lists where in the code the claim comes from. Anything I could not confirm from the code is marked
**unverified**; the implementer must not state it as fact in the PR, and the PR description must repeat the list of
"Try this in game" items at the end of this section.

What the code shows, in one paragraph. The blueprint holds **only combinators** (`blueprint.ts:735-743`: the clock, the lock,
the filter, helper arithmetic combinators for a modulo or subtick clock, one decider per group of inserters, and the fuel
clocks). **No inserters, no machines.** The combinators are already wired to each other (`blueprint.ts:700-728`); the player
wires only each *schedule decider's output* to its inserters, and sets each inserter to be enabled by that signal. The
decider outputs `1` of the inserter's item signal while the clock is inside one of the inserter's wake windows, and nothing
otherwise (`decider-combinator.ts:150-169`, `blueprint.ts:58-66`).

### The steps as the player reads them

Heading: **Put it in your game.** Caption: **Needs Factorio 2.1.** (Always shown; also beside the Copy button.)

1. **Import it in Factorio 2.1.**
   "Press Copy blueprint. In Factorio 2.1, open the blueprint library and import the string: Import string, or Ctrl+V.
   Older versions cannot read these clocks: they use a feature that came with 2.1."
   *Code:* the string is `blueprintFileFor(result)` encoded (`simulation.worker.ts:114`, `blueprint-export.ts:5-21`). 2.1 is
   required: `blueprints/blueprint.ts:4-7` ("the else outputs of a decider combinator, which clocks need, come with 2.1" and
   the version number written into the blueprint), `CHANGELOG.md:72` ("Generated blueprints now need Factorio 2.1"), and both
   mods' `info.json:9` (`"factorio_version": "2.1"`). Today's caption is "Ctrl+V while in blueprint library"
   (`BlueprintOutput.tsx:113`). **Unverified: the exact name of the import control in the 2.1 blueprint library ("Import
   string") and whether Ctrl+V alone works there.**

2. **Pick one blueprint from the book.** *(Only when the string is a book.)*
   "The book holds the same clock twice. The first one, "{label} (modulo clock)", checks windows that repeat against a
   shorter repeating count, so its combinators have far fewer conditions. The other lists every wake window on the plain
   clock. They switch your inserters on at the same ticks. Take the first one unless you want the plain one."
   *Code:* `blueprint-export.ts:5-21` (modulo first, `setActiveIndex(0)` at `:14`, the book's own description at `:18-19`);
   the label suffix `blueprint.ts:730-733`; the modulo variant exists only "when a window repeats within the period"
   (`plan-run.ts:1119-1125`; otherwise the string is a single blueprint and this step is left out). The two are the same
   windows: `blueprint.test.ts:15-60` checks the modulo against the raw windows with the circuit replay. **Unverified in
   game: the harness only ever builds the full-window blueprint** (`scaffold-recordings.game.test.ts:261-263` passes
   `exported.blueprint` and `exported.schedule`), so the modulo variant has been checked by circuit replay but not run in
   Factorio.

3. **Place the combinators next to your build.**
   "Place the blueprint on clear ground near your inserters. It has only combinators: no inserters and no machines. They
   are wired to each other already; do not rewire them. A wire reaches 9 tiles, so keep each combinator within reach of its
   inserters, or carry the wire along power poles."
   *Code:* `blueprint.ts:735-749` (entities), `:700-728` (wires), `:255-256` (`WIRE_REACH_TILES`, "under the 9 of a copper
   wire"). The row is one tile per combinator (`blueprint.ts:490, 523-568, 613-631`), so a big clock is a long row.
   **Unverified: that circuit wires can be carried along power poles at reach.** Say it only if the owner confirms.

4. **Wire the output of each combinator to its inserters.**
   "A combinator described as "Inserter 3 for [item] from [recipe] into [recipe]" switches that inserter on. With a green
   wire, connect its output to each inserter in the list below. Find an inserter by its item and by the machines at its
   two ends. The game keeps only 500 bytes of a description, so use this list: {the wiring list}. The other combinators
   (Clock, Fuel clock, Clock lock filter, and the ones about a modulo or a subtick clock) are the clock itself: leave them."
   *Code:* the description header `entityDescriptionHeaderLines` (`blueprint.ts:100-122`; merged inserters share one
   combinator, "Inserters 1, 2 for …"); the inserter ids per combinator are `ClockSchedule.inserter_combinators`
   (`blueprint.ts:433-441, 751-754`; the harness wires from exactly this, `factorio-harness.ts:270-293`); the green wire
   from the combinator's output to the inserter's circuit connector: `harness.lua:229-236`; the description limit:
   `player-description.ts:1-2`, `CHANGELOG.md` 0.6.0 "cut to the 500 bytes Factorio keeps"; the clock's own parts:
   `blueprint.ts:291-298, 492-503, 576-593, 679-683`, and the harness skips them the same way (`harness.lua:247-250`).
   Fuel inserters are in the list like the others (`blueprint.ts:668`).
   **Unverified: which side of the placed combinator is its output in the 2.1 editor.** The harness uses
   `combinator_output_green` by name, which a player cannot do; the PR describes the owner's finding.

5. **Set each wired inserter to switch on with that wire.**
   "Open the inserter, find Circuit network connection, choose Enable/disable, and set the condition to **Anything > 0**.
   The combinator puts out one of the inserter's item only while the clock is in a wake window, so the inserter works only
   then."
   *Code:* `harness.lua:20-24` (`ANYTHING_POSITIVE`: `signal-anything`, `>`, `0`) and `:238-240` (`circuit_enable_disable =
   true`, `circuit_condition = ANYTHING_POSITIVE`, applied unless the inserter already enables or sets filters by circuit).
   The signal on the wire: `decider-combinator.ts:150-169` (outputs `constant 1` per item) with `blueprint.ts:58-66`.
   **Unverified: the 2.1 GUI wording ("Enable/disable", "Anything").** *If* the build has drills, add: "A mining drill is
   wired and set the same way." **Unverified: the harness wires inserters only** (`blueprint.ts:74` leaves
   `inserter_ids` empty for a drill; `harness.lua` has no drill branch), so a drill combinator is described but never
   wired by the harness.

6. **Leave the other inserters alone.**
   "An inserter that is not in the list runs all the time: it is set to Always on, or it has nothing to wait for. Do not wire
   it. If this clock replaces an older one, set the inserters the old clock switched, and this list does not name, back to
   always enabled, or they stay off for good."
   *Code:* `plan-run.ts:1739-1764` (always-enabled inserters and the ones the config sets to ALWAYS get no windows, so no
   combinator), `CHANGELOG.md` 0.6.0 "Fixed: An inserter or mining drill set to ALWAYS gets no combinator"; the harness
   does the replacement case by hand: `harness.lua:254-258` ("an inserter the removed clock held and the new one does not
   name would never be enabled again").

7. **Know the lock.**
   "The small constant combinator under the clock is the lock. It is off: leave it off. Switch it on to stop the clock;
   no inserter is switched on while it is on. Switch it off and the clock starts again from its beginning, and the first
   period after may be a tick off."
   *Code:* `blueprint.ts:596-602` (the placed lock and its description, which is where "a tick off" comes from),
   `constant-combinator.ts:76-87` (`is_on: false`), `decider-combinator.ts:120-148` (the clock and the filter pass nothing
   while `signal-lock` is present), `blueprint.ts:263-285` (red wires from the lock to every clock and filter).

**When there is nothing to wire** (every inserter is Always on, so `wiring` is empty): steps 4 to 6 are replaced by one:
"This clock has no combinator for your inserters, so there is nothing to wire." Steps 1, 2 (if a book), 3 and 7 stay.

**The wiring list** (inside step 4) has one row per combinator, in order of the first inserter it serves: "Inserter 3",
"Inserters 1, 2". Numbers are the config ids shown as "Inserter N" on Configure (after 1.9 they are the row numbers).
More than 8 rows: the list scrolls in its own box (`max-height`, keyboard focusable, named).

**Try this in game** (copied into the PR description for the owner): (1) the import wording and Ctrl+V; (2) a book:
whether the modulo clock and the plain one switch the inserters at the same ticks; (3) where a combinator's output side is;

## Decisions I made (for the orchestrator to check)

1. **Install steps come from data, not from parsing the blueprint string.** The worker builds `ClockInstallFacts` from the
   generation result (`schedule.inserter_combinators`, `modulo_blueprint`), the same data the in-game harness wires from.
   No engine change. See "Files".
2. **Plain names come from the clock's ranking, not from its id.** The id of a clock says how it is made; the trade-off says
   what it is *for*, relative to the others. Rules in "`clockSummary.ts`". The names are new copy the owner has not seen:
   they use only glossary words, and are constants in one file.
3. **One copy implementation, three buttons.** Copy blueprint exists in the bar, the card and the string tab. They share
   `useCopyBlueprint` (one `copied` state, one stale-confirmation dialog, one warning toast, one announcement).
4. **The bar keeps its Copy button on Results.** It is the plan's "Copy one click away from either view". There are then two
   buttons named "Copy blueprint" on Results (the bar's outlined, the card's filled). Their landmarks differ (header and
   main); the capture scripts must scope them (see "Screens to capture"). 2.7 can revisit.
5. **The install steps are hidden while the results are stale** (1.1): the wiring list names inserter numbers of a build
   that has changed. The card says so in one line and keeps "Copy old clock…".
6. **Timelines are not mounted unless Developer tools are on.** They are heavy (canvas), so this also makes Results quicker.
   The player-facing chart is 2.6's; **between this item and 2.6 Results has no chart** (phase branch only).
7. **`?debug` does not exist today** (`PLAN.md` says "also turned on by `?debug`"). This item adds it.
8. **`ClockAlternativesPanel.tsx` keeps its file and component name** (less churn for 1.6, 1.7, 1.10, 1.11 and the capture
   scripts); only its heading and body change in B.
9. **No data bars** in the wake-ups column (C's suggestion): the plan does not list them and 2.7 owns the visual pass. The
   constant-column fold below is kept (C §2.3).

### Logic (pure, no React)

4. **`utils/installSteps.ts` (new) [A]** and **`installSteps.test.ts`**.

   export type InstallStepId = 'import' | 'book' | 'place' | 'wire' | 'enable' | 'others' | 'none' | 'lock';

   the section above. Rules: `book` adds step `book` after `import`; `wiring` empty replaces `wire`, `enable`, `others` with

5. **`utils/clockSummary.ts` (new) [A; compact-table helpers added in B]** and **`clockSummary.test.ts`**. Imports types
   only from `../worker/types`; `figure`-style rate text from `./numberText` (`formatNumberText`).
   - `type SummaryClock = Pick<ClockAlternativeView, 'id' | 'label' | 'verdict' | 'ranking' | 'beltLabel' | 'assessment' | 'rankingWindowCount' | 'deadlockRisk'>` (narrow, so tests build small fixtures).
   - `plainClockName(clocks: SummaryClock[], index: number, targetRate: number): string`. The first matching rule wins:
     1. rate is off target by more than 0.005 items/s (the 1.14 `MIN_SHORTFALL`, either sign): `Runs at {rate}/s, not {target}/s`;
     2. `verdict === 'no recovery'`: `Does not recover after a jam or when starved`;
     3. `verdict === 'unstable'`: `Does not hold its rate`;
     4. `!ranking.matches_belt_choice`: `For belts that stand still`;
     5. a *contender* is a clock with `ranking.meets_target_rate && ranking.matches_belt_choice`. Among contenders:
        `wake_ups_per_minute` (rounded to a thousandth, like `rank.ts`) equal to the contenders' minimum and not null:
        `Fewest wake-ups`; else `rankingWindowCount` equal to the contenders' minimum: `Fewest wake windows`;
     6. otherwise `Another way to make {rate}/s`.
     Ties give the same name to each tied clock; the engine's name under it tells them apart. Rule 1 comes first because a
     clock that misses the rate is not a trade-off.
   - `clockTechnicalName(clock)`: the engine's `label`, unchanged (kept as a function so the card and the table say it the same way).
   - `recoversOf(clock): { kind: 'yes' | 'no' | 'not-tested'; text: string }`:
     `stable` yes: "Yes: it gets back to its rate by itself after it is starved or jammed."; `no recovery`, no:
     "No: after {lossesOf(clock)} for a while, it does not get back to its rate by itself in the simulator."; `unstable`,
     not tested: "Not tested: this clock does not hold the rate."
   - `makesText(clock, copies)`: `"{rate}/s"` and the sub-line `"all {copies} copies"` (nothing for one copy);
     `wakeUpsText(clock)`: `"{n} a minute"` (rounded) or `"Not counted"`, sub-line `"one copy"`.
   - `beltLine(rule: PickRule | null, beltLabel: string): string` (the slot for 2.4).
   - `differenceFromRecommended(selected, recommended): string`: up to two sentences from, in order: the rate problem
     (`This one makes {x}/s, not {target}/s.`); the wake-up difference when both are counted
     (`It wakes inserters {n} more times a minute than the recommended clock.` / `fewer` / nothing when equal); the belt
     (`It is made for belts that stand still.`); the verdict (`It does not recover…`). Empty list gives "It is not the
     recommended clock."
   - `foldedMakes(rows)` **[B]**: when 3 or more shown rows make the same rate to 2 decimals, returns
     `"All {n} clocks make {rate}/s."`, else `null`; the compact table hides the Makes column when it is not null.
   - `worksOf(clock): { kind: 'yes' | 'caution' | 'no'; text: string }` **[B]**: "Yes"; stable but `!matches_belt_choice`:
     "Only for belts that stand still"; rate off: "Misses the rate ({x}/s)"; `no recovery`: "Needs a restart after a jam";
