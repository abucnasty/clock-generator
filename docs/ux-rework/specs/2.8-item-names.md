## Change
- Every picker (target recipe, each machine's recipe, item pickers for belts, chests, filters, drills and conditions)
  lists and shows the in-game English name: "Logistic science pack", not `logistic-science-pack`. Hovering a row or the
  chosen value shows the id.
- Search matches the name and the id, in any word order, ignoring case, dashes and brackets. "stone wall" finds `stone-wall`
  (the game calls it "Wall"), and "wall" finds it too. The best matches come first.
- Typing a name or an id and pressing Enter in a picker stores the **id**. The config, the localStorage copy, Export, the
  clipboard and every JSON in or out of the page stay in ids, so nothing the sidecar mod or a saved sample uses changes.
- Every place that prints an item or recipe id as text now prints the name, with the id in a native `title` tooltip: the
  stale banner and the copy dialog, the "no inserter bringing in X" messages, the Transfer Plan, Machine Facts, the Fuel
  panel, the diagram nodes, the timelines' legends, the Insights tables, the inserter and entity pickers' sublabels.
- An id the game's text has no name for (mod items like `ee-infinity-chest`, `rcalc-power-dummy`, `parameter-0`) shows a
  sentence-case form of the id ("Ee infinity chest"), made when the data is dumped. An id the page has never heard of,
  such as something the player typed, shows as typed.
- Not changed, and said so in the PR: the engine's own sentences (the titles and prose of the Insights, validation errors
  from the engine, the generator log). They contain ids, and changing them is an engine change (see Risks).

## Decision: where the names come from

**Pick: extract the English locale during the data dump (`filter-raw.js`), with a sentence-case fallback only for the
ids the locale lacks.** Not the rule plus an exceptions map. Why:

- A rule on the id is wrong often enough to need a hand-kept map. Measured against the game's text for the 824 ids the page
  can show: the vanilla ids the plain rule gets wrong include `long-handed-inserter` (a dash that stays),
  `one-way-valve`, `uranium-235` ("Uranium-235"), `shotgun-shell` ("Shotgun shells"), `small-lamp` ("Lamp"), `stone-wall`
  ("Wall"), `teslagun` ("Tesla gun"), `capture-robot-rocket`, `power-armor-mk2`, `fluoroketone-hot` ("Fluoroketone (Hot)"),
  `heavy-oil-cracking` ("Heavy oil cracking to light oil"), and about ten more. Every game update or new mod adds more.
- The ids that collide: recipe `water-barrel` is "Fill Water barrel" while item `water-barrel` is "Water barrel". A rule
  gives one answer for both. The locale route keeps two tables (item, recipe), as the game does.
- The repo already has a manual dump step on a machine that has Factorio (`data-raw-dump.json` is gitignored, made with
  `factorio --dump-data`; `filter-raw.js` turns it into the committed `data-filtered.json`). Reading the install's
  locale there costs the owner nothing new, and the output is **committed**, so CI, the UI build and every contributor
  need neither Factorio nor the locale.
- No new copy step and no new fetch: the names go **inside `data-filtered.json`** as one new top-level key, so
  `scripts/copy-factorio-data.mjs` and `engineClient.ts` (`/data-filtered.json`) stay as they are. The engine ignores
  unknown keys (`FactorioDataService.initialize` stores the object; it does not validate it). Size: about 1,100 names,
  roughly 40 KB on a 1.5 MB file.

What the locale does not have, and the fallback covers: the dump contains mod prototypes (Editor Extensions `ee-*`,
`rcalc-*`, `region-cloner_selection-tool`) whose locale is not in the game folder, and `parameter-0..9`. About 100 entries across the two tables
(mostly the `-recycling` recipes of those mods) get the sentence-case fallback. They are hidden internals nobody should pick. Checked
by running the evaluator described below over the current dump: every other id resolves.

I checked that the dump and the committed file agree: running the current `filter-raw.js` over the current
`data-raw-dump.json` reproduces `data-filtered.json` byte for byte. The installed game is 2.0.77
(`/Applications/factorio.app`); the dump is older. A name that changed between the two would show up as a diff in the
`names` key only, which is what the implementer reviews.

## Files

### clock-generator (the data)

1. **`resources/locale-names.js` (new, CommonJS, no dependencies).** The pure part of the extraction, so a test can reach it:
   - `parseLocale(cfgText): Record<string, string>`: keys are `section.key` (`item-name.iron-plate`). A `[section]` line sets
     the section; `key=value` splits at the **first** `=`; lines starting `;` or `#`, blank lines, and lines before the first
     section are skipped. Values are kept as written.
   - `evaluateLocalised(localised, table): string | null`: a game `LocalisedString`. A string is itself. A list is
     `[key, ...params]`: the key `""` joins its params; any other key looks up `table[key]` and replaces `__1__`, `__2__`…
     with the evaluated params, and `__ITEM__x__`, `__FLUID__x__`, `__ENTITY__x__`, `__EQUIPMENT__x__` with
     `item-name.x`, `fluid-name.x`, `entity-name.x`, `equipment-name.x` (the id itself if absent). **Returns `null`** if the key
     or any param cannot be resolved (so the caller falls back); never throws on a missing key.
   - `buildNames(raw, filtered, table): { names: { item: {...}, recipe: {...} }, fallbackIds: string[] }`:
     - `item` has an entry for every id in `filtered.item`, `filtered.resource`, `filtered['mining-drill']`, and every ingredient
       or result name of every recipe (fluids included). Order: the item's own `localised_name` from the raw dump if it has one
       (barrels: `["item-name.filled-barrel", ["fluid-name.water"]]`), else `item-name.<id>`, `fluid-name.<id>`,
       `entity-name.<id>`, `equipment-name.<id>`, in that order.
     - `recipe` has an entry for every id in `filtered.recipe`: the recipe's own `localised_name` (recycling recipes:
       `recipe-name.recycling` with the product), else `recipe-name.<id>`, else the name of the recipe's `main_product`, else of its
       only result (the same item/fluid/entity lookup as above), as the game does.
     - Anything still unresolved gets `sentenceCase(id)` (first letter upper case, `-` and `_` to spaces) and its id goes in
       `fallbackIds`.
     - Keys are written in sorted id order so a regenerated file diffs cleanly.
2. **`resources/filter-raw.js`.** After the existing mapping, read the locale and add `filtered.names = buildNames(...).names`. The
   existing keys and values must not change. The game folder comes from the `FACTORIO_DATA_DIR` environment variable
   (default `/Applications/factorio.app/Contents/data`); if it does not exist, stop with a message that says to set the
   variable. Read `<dir>/<mod>/locale/en/*.cfg` for `core`, `base`, `elevated-rails`, `quality`, `space-age` in that
   order (a later file wins). Log how many names came from the locale and the `fallbackIds` it used, so the owner sees
   them. `knip.json` already lists `resources/filter-raw.js` as an entry and `resources/*.js` as project files, so the new
   module is used, not dead.
3. **`resources/data-filtered.json` (regenerated).** `cd clock-generator/resources && FACTORIO_DATA_DIR=... node filter-raw.js`.
   The diff must be **only** the new `"names"` key at the end. Check with a script that deletes `names` from the new file
   and compares the rest with the old file, and say so in the PR.
4. **`src/data/locale-names.test.ts` (new).** Loads the module with `require('../../resources/locale-names.js')` (the package
   is CommonJS, and `src` has no `allowJs`; do not import it with `import`). Tests under Tests.
5. **`README.md`** (one line, optional): the data section (around line 454) mentions the `names` key and `FACTORIO_DATA_DIR`.

### clock-generator-ui (the lookup, then the sites)

6. **`utils/gameNames.ts` (new, pure, no React).** Exports, with doc comments:
   - `interface GameNames { item: Record<string, string>; recipe: Record<string, string> }` and `NO_NAMES` (both empty).
   - `itemName(names, id)`: `names.item[id]` or `id`. `recipeName(names, id)`: `names.recipe[id]`, else `names.item[id]`, else `id`.
     `iconName(names, id)` (for `FactorioIcon`, whose name is an item or a recipe): item, else recipe, else `id`.
     **Own properties only** (`Object.hasOwn`), so `constructor`, `toString` and `__proto__` come back as typed.
   - `normalizeForSearch(text)`: lower case, `-`, `_` and punctuation such as `(` `)` `,` to spaces, runs of spaces to one,
     trimmed. "Fluoroketone (Cold)" and `fluoroketone-cold` both give `fluoroketone cold`; "Uranium-235" gives `uranium 235`.
   - `matchesQuery(query, id, name)`: true if the query is empty, or **every** word of `normalizeForSearch(query)` is a
     substring of `normalizeForSearch(name) + ' ' + normalizeForSearch(id)`. Word order does not matter.
   - `searchIds(query, ids, label)`: `ids` that match, best first. Tiers, in order: the whole query equals the name or the id;
     the name starts with the query; the id starts with it; a word of the name starts with it; any other match. Within a
     tier, the order of `ids` is kept. An empty query returns `ids` unchanged. `label` is `(id) => string`.
   - `resolveTyped(input, ids, label)`: for a freeSolo picker's Enter. Trimmed `input` that is an id returns it; one whose
     normalised form equals the normalised form of exactly one id or one name returns that id; anything else (empty, unknown,
     an ambiguous name) returns the input as typed, so the engine's own "unknown recipe" message still appears.

## Risks and checkpoints
- **Checkpoint: a data-dump change.** `filter-raw.js` is the dump and `data-filtered.json` (which the engine, its tests and the page all read) gets a new key. It is
  additive and the old content is byte-identical, but it is the owner's data pipeline and a 1.5 MB committed file, and the dump now needs the game folder
  (`FACTORIO_DATA_DIR`). Ask the owner to approve the approach before the implementer starts. This does not add a copy step, a fetch, a dependency, CI or `.claude` change.
  The recommendation is the extraction above; the fallback if the owner declines is the rule plus an exceptions map in `gameNames.ts`
  (20 to 30 vanilla exceptions, the ones listed in this spec and a few equipment and barrel names), with the same API, so everything below the `names` key stays the same.
- **Size.** About 42 files; see the top. The wide, mechanical part is step 12; the risky part is `ItemSelector` (steps 10 and 11), which every picker uses.
- **freeSolo.** The pickers are `freeSolo`: today Enter stores whatever was typed. `resolveTyped` must run on that string, or "Logistic science pack" would be saved
  as a recipe name the engine does not know. Typed text that matches nothing is still stored as typed, as now. The `iconOnly` picker returns `''` from `getOptionLabel`
