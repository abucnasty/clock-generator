## What the data gives us (checked in the engine, no engine change needed)

| Need | Where it is | Verdict |
|---|---|---|
| Windows of every inserter and drill, in ticks of one clock period | `ClockAlternativeView.clockWindows` (`SerializableClockWindows` = `Record<entityId, {start, end}[]>`). Built by `serializeClockWindows(withInserterClocks(...))` in `clock-generator/src/crafting/plan/plan-run.ts`. `start` and `end` are **both inclusive**, so a window's length is `end - start + 1` (the timeline draws it the same way, `StateTransitionTimeline.tsx:419`). Keys are `"inserter:3"`, `"drill:1"` (`EntityId.id`) | Have it |
| What is *not* in `clockWindows` | An inserter left always enabled (or set to ALWAYS in its rule) has no entry. | Period | `ClockAlternativeView.simulationDurationTicks` (= `result.simulation_duration.ticks`; **fractional** for a subtick clock, e.g. 550.957). `cycleTicks` is the crafting cycle, not the period | Have it |
| **Wake-ups per minute per inserter** | `ClockAlternativeView.asBuilt.wake_ups.inserters[]` (`InserterWakeUps`: `inserter_id`, `wake_ups_per_minute`, `alarms_per_minute`, `enabled_share`, `waiting_share`). `asBuilt` already reaches the page (`simulation.worker.ts:110`). No engine change.** Same source as the table, so the rows add up to the table's number |

(2) Counted for **inserters only**; a drill has no figure. (3) It is per inserter, not per window: it cannot say which window woke it. | Names, ends and items of a row | `ClockAlternativeView.stateTransitionHistory.entities[]`: `entity_id`, `entity_type` (`'inserter' \| 'machine' \| 'drill'`), `label` ("Inserter 3", "Drill 1 (iron-ore)"), `source.label`, `sink.label`, `items` | Have it. After 1.9 the number in the label is the list position |

**Wake-up is provisional** (1.12, "Owner's glossary decisions", item 1). The owner will write a strict definition after a separate
experiment; the code's own comment in `wake-ups.ts` says the number of lists an inserter sleeps on "has not been read yet". So:
the view shows only the engine's `wake_ups_per_minute` and carries **no wake-up arithmetic of its own**, so a changed engine
definition flows through unchanged; and **every user-facing definition and every sentence that explains a wake-up lives in one
module, `utils/wakeWindowCopy.ts`** (below). Changing the definition later is a one-file edit.

## Change

- **A new "Wake windows" view** for the selected clock, the first and default tab of Results (`ResultsWorkspace` default tab changes
  from Timelines). 2.5 later moves it below the summary card; the component takes the selected clock as a prop and assumes no layout.
- **Rows and axis.** One row per inserter, then per drill, in number order. All rows share one axis: 0 to one clock period, with
  tick marks labelled in ticks and, on a second line, seconds ("0 s", "1.67 s"). Each wake window is a solid bar. The last N ticks
  of a window that is belt slack are drawn hatched (stripes, not a second colour). A row has the label ("Inserter 3"), what it moves
  and between what ("Iron plate: Belt 1 to Machine 2"), the bars, and on the right **On for 14%** and **Wake-ups/min**.
- **Rows that have no bars say so in words**, on the same line: "Always on: not on the clock", "Own clock: on 6 ticks every 400
  (fuel)", "Never switched on".
- **A "what to watch for" note** under a row when something applies: a window that fills the whole period or an inserter on for
  80% or more of it ("the clock does little here"), belt slack ("+4 ticks"), a very short window, a window that wraps past the end
  of the period, the row with the most wake-ups. Notes have an icon and words (never colour alone) and are written in the
  glossary's terms.
- **Click, tap or arrow key selects a window** and opens its details under its row: "Window 2 of 3: ticks 212–240 (29 ticks, 0.48 s),
  of which the last 4 ticks are belt slack. The inserter reacts 2 ticks after the window opens."
- **"Show as table"** (a switch) swaps the chart for two real tables (a row per inserter; a row per window), with the same numbers.
- **Accessibility, concretely.** Every row has a full text summary as its accessible name. The chart is one tab stop (roving
  focus): Tab enters, Up and Down move between rows, Left and Right step through the windows of a row, Home and End jump to the
  first and last window, Escape clears the selection. A polite live region speaks the selected window. No information is hover-only.

## Visual spec (dark theme; measured with the formula `lib.mjs` `contrast()` uses, WCAG relative luminance)

The view sits in a `Paper variant="outlined"` (background `#232323`, no elevation overlay, so the numbers below are exact; keep it
outlined or the overlay shifts them). All graphics ≥ 3:1 against `#232323`; the capture measures the painted colours (see "Screens to capture").

| Element | Colour | On `#232323` | Rule | Not colour alone because |
|---|---|---|---|---|
| Wake window bar | `#56B4E9` (Wong sky blue, from `colors.ts`) | **6.81:1** | 1.4.11 ≥ 3:1 | Position on a labelled axis, the row's text summary, and the table |
| Belt slack part of a window | the same `#56B4E9` as 45° stripes, 3px on / 3px off, plus a 1px outline of the same colour | 6.81:1 | 1.4.11, 1.4.1 | **Pattern** (hatched vs solid), the legend, and "+N ticks" in the row's text |
| Row track (the whole period) | 1px outline `#8c8c8c`, no fill | **4.67:1** | 1.4.11 | Shows the period's extent so "off" is a visible gap; the numbers also say it |
| Selected window | 2px outline `#fca300` (theme `primary.main`), 2px gap, bar 6px taller | **7.77:1** (measured against the paper the outline sits on, not against the bar, which it does not touch) | 1.4.11, 2.4.7 | The bar is taller, and the details open under the row |
| Row focus ring | theme `:focus-visible` ring from 1.11 (2px `#fca300`, 2px offset) | 7.77:1 | 2.4.7 | It is the focus ring |
| Axis tick marks and labels, secondary text | `text.secondary` (`rgba(255,255,255,0.7)` = `#bdbdbd`) | **8.37:1** | 1.4.3 (4.5:1), 1.4.11 | Labels are text |
| Row label, numbers, notes | `text.primary` `#ffffff` / `text.secondary` | 15.72 / 8.37:1 | 1.4.3 | Text |
| Vertical grid lines behind the rows | `rgba(255,255,255,0.12)` (≈ 1.4:1) | decorative | 1.4.11 does not apply | They repeat the axis ticks; `aria-hidden`. If an auditor objects, drop them |

Why this hue: orange is the selection and focus accent and green is "confirm" (PLAN "Visual direction"), so neither may mean "on".
Sky blue is already in the repo's Wong palette and is 6.81:1. The developer timelines use `#56B4E9` for the drop-off phase; that
chart moves behind Developer tools in 2.5, and 2.10 gives its items their own palette, so the two never sit together. White text on
a sky-blue bar would be 2.31:1, so **no text is drawn inside a bar**; labels sit beside or under it.
There is one series (the windows), so no categorical palette and no per-inserter colour: the row label identifies the inserter.
Minimum drawn width of a bar is 4px so a 1-tick window is visible; its true length is in the text.

## Files

All under `clock-generator-ui/src`. **New: 8 files (3 components, 2 utils, 2 tests, 1 capture script). Changed: 3.**

### New

1. **`utils/wakeWindows.ts`** (pure, no React, type-only imports from `clock-generator/browser`; the logic the tests cover).
   - Types:
     - `WakeWindow { start; end; length; segments: {start; end}[]; wraps: boolean; slackTicks: number }`. `start`/`end` are the
       logical window (for a wrapped pair `end < start`); `length` is the total ticks; `segments` is what is drawn (1 or 2 bars);
       `slackTicks` is the part of the window's **end** that is belt slack (0 when none).
     - `WakeWindowRow { id; kind: 'inserter' | 'drill'; number; label; detail; windows: WakeWindow[]; mode: 'windows' | 'always-on' | 'own-clock' | 'never'; ownClock?: { windowTicks; everyTicks; perMinute; item }; onTicks; onShare; wakeUpsPerMinute: number | null }`. `detail` is "Iron plate: Belt 1 to Machine 2" (`items`, `source.label`, `sink.label`; a drill: its sink).
   - `normalizeWindows(raw: {start;end}[], period: number): WakeWindow[]`. Sorts, clamps to the period (windows from
     `clockWindowsOverPeriod` can run past it), merges overlapping or touching windows (as `OpenRange.reduceRanges` does), then merges a
     window that ends on the period's last tick with one that starts at tick 0 into one window with two `segments` and `wraps: true`.
     Drops a window with `end < start` after clamping. Fractional period: the last tick is `Math.floor(period)`.
   - `windowLengthTicks(w)`, `ticksToSeconds(ticks)` (÷ 60), `coverage(windows, period)` (0 to 1, a wrapped window counts once).
   - `buildWakeWindowRows(alternative: Pick<ClockAlternativeView, 'clockWindows' | 'stateTransitionHistory' | 'asBuilt' | 'fuelView' | 'beltPickupSlackTicks' | 'simulationDurationTicks'>): WakeWindowRow[]`.
     The ids are the union of the inserter and drill entities of `stateTransitionHistory`, the keys of `clockWindows`, the inserters of
     `asBuilt.wake_ups` and of `fuelView.plan.inserters` (so a row is never lost when one source misses it). Order: inserters by
     number, then drills by number. Mode: key present with windows → `windows`; present and empty → `never`; in `fuelView.plan.inserters`
     and not in `clockWindows` → `own-clock`; otherwise `always-on`. `slackTicks` = `min(beltPickupSlackTicks[id] ?? 0, window length)`,
     only for a whole-tick period (the engine only applies it then). `wakeUpsPerMinute` from `asBuilt.wake_ups.inserters`, else `null`.
   - `sumWakeUps(rows): number | null` (null when any inserter row lacks a figure) and `wakeUpsCounted(alternative): boolean`.
   - `axisTicks(period: number, maxMarks: number): number[]`. Marks at a "nice" step (1, 2, 5 × 10ⁿ ticks) so there are at most
     `maxMarks`, always including 0; the end of the period is labelled separately.
   - `tickAtFraction(fraction, period)`, `nearestWindowIndex(windows, tick, toleranceTicks): number | null`, and
     `stepWindow(current: number | null, count: number, key: 'next' | 'previous' | 'first' | 'last'): number | null` (stops at the ends, no wrap;
     `null` when `count` is 0).
2. **`utils/wakeWindowCopy.ts`** (**the one place for every string the view shows**; plain constants and small pure builders, nothing else).
   - **Definitions that can change:** `WAKE_WINDOW_DEFINITION` ("A stretch of ticks during which the clock switches an inserter on."),
     `WAKE_UP_DEFINITION` (the approved provisional wording from 1.12 row 5, option (b); copy it from the glossary once 1.12 Part B is

   - Everything else: the heading and intro, the legend labels, the keyboard hint ("Left and right arrow keys step through the windows
     of a row. Tap a bar for details."), the switch label ("Show as table"), the table captions and headers, the empty and "Not counted"
     messages, the notes, the live-region sentence.
   - Builders: `rowSummary(row, periodTicks): string` (the row's accessible name), `windowDetails(row, index, periodTicks): string`,
     `watchNotes(row, ctx): { id; text }[]` with `ctx = { periodTicks; mostWakeUpsId: string | null }`, `periodText(ticks)`

   - Names: "Wake window", "Wake-up", "belt slack", "clock period", "swing", "Always on" follow the approved glossary (1.12). The notes:
     - whole period, or on for ≥ 80% (`MOSTLY_ON_SHARE`, the engine's own `MOSTLY_ENABLED_SHARE`): "On for 97% of the clock period, so the clock

## Behaviour details

- **Axis.** `maxMarks` is 6 at the 720 layout and 10 at 1440; marks use `axisTicks`. First line "0, 100, 200 ticks", second line seconds.
  The right end of the track is the period; a text "Period: 600 ticks (10 s)" sits at the axis end.
- **Fractional period** (subtick clock): the axis end reads "550.96 ticks (9.18 s)"; windows are still whole ticks and are drawn on
  `period`, so the last tick sits at the right edge.
- **Layout.** At 1000px and wider: a grid `[label 220px | chart 1fr | numbers 150px]`. Below that (including 720): label and numbers on one
  line, the chart full width under them. The page never scrolls sideways; the chart is fluid, never fixed-width (1.4.10 Reflow at 320 CSS px).
- **Keyboard.** The chart is `role="group"` named by its heading and described by the hint. Each row is `role="group"` with
  `aria-label={rowSummary(...)}`, `tabIndex` 0 for the active row and -1 for the others (roving), and the bars are `aria-hidden`. The row
  gets focus on Tab (the first time: the first row; after that, the last focused row). Keys on a focused row:
  Left/Right = `stepWindow` previous/next (the first Right selects window 1), Home/End = first/last window, Up/Down = previous/next row
  (the selection moves with a row: it clears), Escape = clear the selection. Nothing else is bound; no single-key shortcuts while the
  row is not focused (2.1.4).
- **Pointer and touch.** A click or tap on a row's track calls `tickAtFraction` then `nearestWindowIndex` with a tolerance of 12px
  expressed in ticks; inside the tolerance it selects that window, outside it clears the selection. It also moves roving focus to that row.
  The whole track is the target (row height ≥ 32px), so a 1-tick window is tappable (2.5.8).
- **Details.** Under the selected row, a panel (`windowDetails`): window n of N, start–end tick and seconds, length, slack part, "The inserter
  reacts 2 ticks after the window opens" (`CIRCUIT_LATENCY_TICKS`, the same wording as the timeline's legend), and the row's notes. One
  visually hidden `aria-live="polite"` element (**not** `role="status"`, so 1.11's single status region stays single) always exists and gets
  the same sentence when the selection changes; the visible panel is not live.
- **Notes** are shown under every row that has one (not hidden behind selection), as an icon + text line. Rows with none show nothing.
- **Table view.** `FormControlLabel` + `Switch` labelled "Show as table" (label never changes, so its state is the switch's `checked`).
  The chart unmounts, the tables mount; focus stays on the switch. Table 1 (caption "Wake windows by inserter and drill"): columns
  Name · Moves · On for (% of the period) · Windows (count) · Wake-ups/min (1 copy) · Notes. Table 2 (caption "Every wake window"): Name ·
  Window (n of N) · Starts at tick · Ends at tick · Length (ticks) · Length (s) · Belt slack (ticks). Real `<table>`, `<caption>`, `<th scope="col">`
  and `<th scope="row">` for the name cell. A wrapped window is one row with "Ends at tick 4 (next period)". On a narrow screen the tables
  scroll inside their own container (`overflow-x: auto`, `tabIndex={0}` and an `aria-label`), never the page.
- **No clock yet / generating.** `alternative === null`: render nothing (the Results empty state already speaks). While other clocks are
  pending the view shows the selected one.
- **A clock with no wake-up count** (`asBuilt?.wake_ups` absent): the "Wake-ups/min" cell reads "Not counted", and one line under the summary
  says why: "This clock was not run long enough to count wake-ups." (The count needs a clock that holds its rate over a long run.)
- **Drills:** "Wake-ups/min" reads "Not counted for drills" in the row and "–" is never used alone.
- **Results from an older build:** the view just shows the selected clock; the `StaleResultsBanner` above it already warns.

## Acceptance criteria

- [ ] Results opens on **Wake windows** for a generated clock; Timelines is still a tab (2.5 moves it).
- [ ] One row per inserter then per drill of the selected clock, in number order, named like the List ("Inserter 3"), including rows for
      inserters that are always on, never on, or on a clock of their own; none of them is missing (compare the row count with the entities of `stateTransitionHistory`).

      wraps the period is one window in the text and two bars; a 1-tick window is visible (≥ 4px).

- [ ] **Status (4.1.3):** selecting a window changes the text of one `aria-live="polite"` element to the details sentence; there is still exactly
      one `role="status"` on the page.
- [ ] **Not colour alone (1.4.1):** with the page forced to grayscale, bars, slack, selection and notes are still told apart (solid vs hatched
      vs taller outlined; icons + words). The legend shows the shape of each.
- [ ] **Contrast (1.4.3, 1.4.11):** the painted colours match the table above and are ≥ 3:1 (graphics) and ≥ 4.5:1 (text) on `#232323`.
- [ ] **Touch (2.5.8):** tapping within a row's track selects the nearest window within 12px; the switch and the rows are ≥ 24px tall.
- [ ] **Table:** "Show as table" shows both tables with the same numbers as the chart; the switch keeps focus; turning it off restores the chart
      with the selection cleared.
- [ ] At 1440 and 720 the page does not scroll sideways (`noSideScroll`); the tables scroll inside their container.
- [ ] Every definition and explanation of a wake-up or wake window comes from `utils/wakeWindowCopy.ts`; the components contain no such prose.
- [ ] `npm test`, `npm run lint`, `npm run knip`, `npm run check:icons`, `npm run build` pass in `clock-generator-ui`. The engine is unchanged, so its checks are not required.

## Tests

Vitest only, no jsdom: both files are pure functions over plain objects. Build fixtures as small literals typed with the exported types.

**`utils/wakeWindows.test.ts`**
- `normalizeWindows`: sorts unsorted input; merges overlapping and touching windows (`[0,9]` and `[10,19]` → one of 20); clamps a window that runs past
  the period; drops an inverted one; leaves an empty list empty.
- Wrap: period 100, `[{0,4},{96,99}]` → one window, `wraps: true`, `length` 9, two `segments`, `start` 96, `end` 4. A lone `[0,4]` does not wrap.
- A single window `[0, period-1]` has `coverage` 1; two windows of 29 in 600 have coverage 58/600.
- Fractional period (550.957): last tick is 550; length and coverage use `period`.
- `buildWakeWindowRows`:
  - orders inserters then drills, numerically (`inserter:10` after `inserter:2`);
  - mode `always-on` for an entity with no entry, `never` for an empty list, `own-clock` for a fuel inserter in `fuelView.plan.inserters` and not in `clockWindows`;
  - a row exists for an id that only `asBuilt.wake_ups` or only `clockWindows` knows;
  - `wakeUpsPerMinute` taken by id; `null` when `asBuilt` is null, when `wake_ups` is absent, and for a drill;
  - `slackTicks` = slack capped at the window length; 0 for a fractional period; 0 for an inserter not in the record.
- `sumWakeUps`: the rows of a fixture add up to `wake_ups.wake_ups_per_minute`; `null` when one inserter lacks a figure.
- `axisTicks`: includes 0; never more than `maxMarks`; steps are 1, 2 or 5 × 10ⁿ (periods 60, 168, 600, 2240, 550.957, 1); never beyond the period.
- `tickAtFraction` clamps to 0 and the period; `nearestWindowIndex` picks the closer window, honours the tolerance, returns `null` outside it and for no windows.
- `stepWindow`: next/previous stop at the ends (no wrap), first/last, from `null`, and `null` for zero windows.

**`utils/wakeWindowCopy.test.ts`**
- `rowSummary`: one window / several windows (plural "1 window", "3 windows"), always-on, never, own clock ("6 ticks every 400"), a wrapped window,
  "Not counted" wake-ups, and the cap ("and 3 more" after 4 windows). No `NaN`, `undefined` or more than 3 decimals in any output.
- `windowDetails`: start, end, length in ticks and seconds, the slack part only when `slackTicks > 0`, the 2-tick reaction sentence.

## Risks and checkpoints

- **No owner checkpoint is tripped.** No new dependency, no CI/release/settings change, no engine change. The plan's allowance for engine changes is not used. One
  deviation worth the orchestrator's glance: the plan says "the wake-ups per minute" per row; the engine counts them **per inserter over a long run**, so a clock with no long
  run (not holding, or a very long period) and every drill show "Not counted". Making a drill count would be an engine change (`wakeUpsOfStock` takes inserters only) and the
  owner's wake-up experiment may change what is counted anyway; recommend leaving it and adding it to the experiment's follow-ups.
- **Wake-up is provisional (1.12).** Everything that defines or explains it is in `utils/wakeWindowCopy.ts` (3 definition constants + the "few wake-ups saved" sentence in the
  mostly-on note). Whoever updates the glossary updates that file; 2.5's `glossary.ts` should import from it rather than copy. The numbers need no change when the definition does.
- **Shared file with 2.5: `ResultsWorkspace.tsx`.** Both items edit it. Whichever merges second resolves the conflict (ORCHESTRATOR "Items may share files"). Suggested order:
  2.6 first (a small, additive tab) so 2.5 moves an existing tab below its summary card; otherwise 2.6 mounts `WakeWindowsView` where 2.5 put it. `WakeWindowsView` is layout-free
  on purpose.
- **Also overlapping:** 1.11 (the heading outline and the focus ring this view relies on: if 1.11 has not merged the ring is the browser default, which is fine but must be rechecked),
  1.9 (the number in "Inserter N"; the view reads the label as given), 1.12 Part B (check the strings against the glossary), 1.10 (`WAKE_UPS_HEADER`), 2.10 (separate timelines; no
  shared code), 2.8 (item names: show `items` through the helper 2.8 adds if merged, else the raw id; icons are decorative, `alt=""`).
- **Roving focus on `role="group"`.** A focusable group named by a long label is read by NVDA/JAWS/VoiceOver as "Inserter 3, …, group". The implementer checks it with VoiceOver on the preview;
  if a screen reader reads the label twice, move the summary to `aria-label` on a single child with `role="img"` and keep the roving on the wrapper. Do not nest interactive elements inside.
- **Long labels.** A row with many windows (a modulo clock can have dozens) makes a long accessible name; hence the cap of 4 listed windows in `rowSummary`. The table lists them all.
- **Fractional periods** draw `period` as the axis end while windows are whole ticks; a window can touch the right edge by up to one tick of error. Fine; the text has the exact ticks.
- **Performance.** Rows ≤ about 40 and windows ≤ a few hundred; plain DOM, no canvas. If a modulo clock has thousands of windows, merge bars under 1px wide in the drawing only (the data keeps them).
