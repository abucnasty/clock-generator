## What is wrong today

- **A1.** The first screen is a form headed "Target Output" and two grey buttons. Nothing says what the tool does or
  where to start. The only guidance sits below the fold in the Validation panel.
- **A2.** The Sidecar mod is named nowhere in the UI. "Paste from Factorio" is a ⋮ item next to "Reset Configuration".
  A clipboard with no export gives a 4-second toast, "Clipboard does not contain valid JSON. Make sure to copy from the
  Factorio mod." (shot 06), which does not say which mod or how.
- **A4.** `clock-generator/resources/config-samples/science/` holds configs for nine science packs. The site offers none
  of them, so a science player starts from one empty machine.
- **A15.** "Import Config" and "Export Config" are the loudest controls on the first screen, but a newcomer has no config
  file. A mod export saved to a file is refused by Import Config.
- **A17.** Paste never sets Target Output, so even a mod user still faces an empty "Recipe *". The old-mod warning
  contradicts itself: "This was exported by Clock Generator Sidecar 0.6.0. Nothing in this import is affected by that.
  Update the mod to 0.7.0 to import everything automatically." (`sidecar-version.ts`, `newerSidecarStep` and
  `checkSidecarImport`.)

## Change

- **An intro card above Target Output** on the Configure view, with a close button:
  - One sentence on what the tool does, then three numbered steps: get your build in, Generate, copy the blueprint and
    wire it to your inserters. Step 1 holds the Sidecar steps: Alt+E, drag over the build, Copy JSON, Ctrl+C, then click
    Paste from Factorio.
  - A link to the mod portal page (<https://mods.factorio.com/mod/clock-generator-sidecar>, opens in a new tab) that
    says it needs Factorio 2.1.
  - **Paste from Factorio** is the one filled green button. **Try an example** (outlined) and **Build by hand** (text)
    are secondary.
  - Closing it is remembered in this browser. It only shows while the build is still blank (nothing entered), so a
    returning player with a saved build never sees it. Reset brings it back unless it was closed. "Getting started" in
    the ⋮ brings it back on demand.
- **Paste from Factorio is a top-level app bar button** (filled green, "Paste" below 600px) and leaves the ⋮.
- **When the clipboard cannot be read or holds no export, a dialog opens, not a toast.** It says why in one line, gives
  the mod link and the steps, and has a box to paste into. Pasting into the box carries on at once. A build file pasted
  by mistake gets its own line ("use Open build file…").
- **"Try an example"** opens a list of the nine science builds. Picking one replaces the build (with Undo) and lands on
  Configure.
- **Import Config and Export Config become "Open build file…" and "Save build file"**, always in the ⋮ (no buttons in the
  bar at any width). Reset Configuration becomes "Reset build". Opening a Sidecar export saved to a file hands it to the
  paste flow instead of failing.
- **The paste confirm dialog has a Target Output row**, pre-filled from the export (2.2) or, for older exports, worked
  out from the machines. It is ticked when Target Output is still empty and unticked (with a note) when the player
  already set one.
- **The old-mod warning no longer contradicts itself** (A17).

## Interface needed from 2.2 (not read from its spec)

The export gains one optional top-level key, read by the UI from the parsed clipboard JSON. The UI does not need the
engine to carry it, so 2.1 does not depend on 2.2's engine work:

```json
"suggested_target": { "recipe": "logistic-science-pack", "items_per_second": 22.968749, "copies": 1 }
```

- `recipe`: a recipe name in the game data, the final product of the selection (the recipe whose output leaves the
  selection).
- `items_per_second`: finite, above 0. The total full-speed output of every exported machine making that recipe, as
  `Machine.computeMachineFacts(...).output_rate_per_second` gives per machine (crafting speed, recipe time, productivity).
- `copies`: an integer of at least 1 (the mod writes 1).
- Anything else (missing, wrong type, a recipe the game data lacks) is ignored and the UI infers a target from the
  machines. Older exports have no key. If 2.2 chooses another key or shape, change `SUGGESTED_TARGET_KEY` and the reader
  in `utils/suggestedTarget.ts` only.

## Decisions

**Examples: extend the existing copy step, not a static import.** `scripts/copy-factorio-data.mjs` already runs before
`npm run dev` and `npm run build` (`predev`, `prebuild`; Vercel runs `prebuild` too), and the owner already runs it by
hand because `ignore-scripts` is on. Extend it to also copy the nine example configs to `public/examples/` and write
`public/examples/index.json`. That adds **no new manual step and no new script**; the files are gitignored like
`public/data-filtered.json`. The page fetches them when "Try an example" opens, so they are not in the main bundle.
A static import (`import.meta.glob('../../clock-generator/resources/config-samples/...')`) was rejected: the files sit
outside Vite's root, and the dev server's `server.fs.allow` refuses them without a `vite.config.ts` change, which also
puts the JSON in the bundle. Without the script run (`public/examples/index.json` missing), Vite's dev server answers
with `index.html`; the manifest reader must treat that as "no examples" (see Files).

**The nine examples** (one per pack, simplest first so a newcomer's first Generate is quick): logistic-science,
automation-science, utility-science, chemical-science, electromagnetic-science, military-science
(`military-science-1-inserter.json`), production-science, metallurgic-science, agriculture-science. All are
`science/<pack>/<pack>.json` except military. The plan names the whole `science/` folder; this is its nine builds, not
the variants.

**Where the entry points live.** `ConfigImportExport` keeps the file input, the confirm dialog and the flows. The intro
card is in `App.tsx`, so `ConfigImportExport` exposes an imperative handle through a `ref` prop (React 19):
`{ pasteFromFactorio(), openExamples(), openBuildFile() }`. The handle's `pasteFromFactorio` must call
`navigator.clipboard.readText()` synchronously from the click (no `await` before it), or the browser refuses.

**Fallback target (older exports).** Pure function, in order:
1. Look up each pasted machine's recipe (`getRecipeInfo`, the lookups the page already holds; a recipe with no info or
   no recipe is skipped).
2. A recipe is *intermediate* when every one of its results is an ingredient of a different recipe among the pasted
   machines. The *final* recipes are the others.
3. Exactly one final recipe gives a suggestion; zero or several give none (a wrong guess is worse than an empty row).
4. Rate = the sum of `output_rate_per_second` (engine `machine-facts` query, via `askEngine`, as
   `useMachineFacts.ts` does) over the pasted machines making that recipe, **floored to 3 decimals** so it never asks
   for a hair more than the machines make. Copies = 1.

**Dismissal rules** (beyond the plan's "dismissible and remembered"; the orchestrator confirms):
- Shown when `!dismissed && blank && !builtByHand`, or when brought back from the ⋮.
- `dismissed`: the close button, stored in `localStorage` under `clock-generator-intro-dismissed`, read and written inside
  try/catch (storage can be blocked).
- `builtByHand`: "Build by hand" hides the card for this visit only and focuses the Target Output recipe input. It is
  not stored, so a later visit still shows it.
- `blank`: no target recipe, every machine's recipe empty, and no inserters, belts, chests or drills.
