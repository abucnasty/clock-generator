## The engine question: do rules reach the blueprint?

**No. A rule shapes only the planning simulation; the blueprint gets the windows the simulator saw the entity move items in.**

| Step | Evidence | What it means |
|---|---|---|
| The planning run puts every inserter and drill with a non-Auto rule on that rule | `clock-generator/src/crafting/plan/plan-run.ts:587-656` (`withEnableControls`, routing to `ConfigurableEnableControlFactory` at :637-650); `crafting/sequence/interceptors/configurable-enable-control-factory.ts:70-87` | Clocked and Conditional rules are run in the simulator, nowhere else |
| The clock's windows are read off that run's transfers, not off the rule | `plan-run.ts:989-990` (`planRun` → `windowsFromHistory`), `:1753-1767` (`OpenRange.reduceRanges(transfers.map(t => t.tick_range))`) | A Clocked inserter that is on for ticks 0–100 but swings in 10–30 gets a 10–30 window; a Conditional rule becomes the ticks it happened to be true and the inserter swung |
| The blueprint is built from those windows only | `plan-run.ts:1100-1118` (`exportClock` → `blueprintForWindows` → `createSignalPerInserterBlueprint` with a history made of the windows) | No rule, no condition, no range is written into any combinator |
| The checks run the build the way the blueprint drives it | `crafting/trial.ts:422-460` (`buildAsBuiltConfig`: "entities with a decider window get a CLOCKED window shifted by the circuit latency, everything else is left unwired (ALWAYS), except explicit NEVER overrides"); `trial.ts:99-109` (`runClockOnBuild`) | The verdicts on Results are for the windows, not for the rule |
| Always on gets no window, so no combinator | `plan-run.ts:1743-1747` (`alwaysEnabledByConfig`), `:1761` | Matches today's "with no combinator in the blueprint" |
| Never on: no transfers, so no window, so no combinator; the checks keep it off | `crafting/sequence/inventory-transfer-history.ts:134-141` (an entry is made only by a transfer); `trial.ts:456` | The blueprint does nothing to keep it off: the player must |
| A Clocked rule's period defaults to one crafting cycle; ranges past it are clamped with a `console.warn` only | `configurable-enable-control-factory.ts:93-106` | B8's silent clamp, confirmed |
| Ranges are inclusive at both ends, positions `0` to `period - 1` | `control-logic/enable-control.ts:68-73` (`clockPosition`), `:76-90` (`rangeLookup`); `data-types/open-range.ts:5-7` | A 1-tick window (start = end) is valid; `end = period` behaves as `period - 1` |
| A Conditional rule needs an inserter: on a drill it throws | `plan-run.ts:637-641` (drill branch calls `createForEntityId(drill_state.entity_id)` with no inserter) → `configurable-enable-control-factory.ts:80-82` (`assert(inserter !== undefined …)`) | Generation fails for any drill with a Conditional rule; the editor offers it today |

Two consequences the design uses: (1) the editor says plainly that the rule is not copied into the blueprint, per mode;
(2) a Clocked rule whose period does not fit a whole number of times into the clock period cannot be reproduced by a
blueprint that repeats every clock period (the windows are read over one period, `plan-run.ts:1753-1767`), so the editor warns.

list runs all the time … Do not wire it", `utils/installSteps.ts` on `origin/feat/ux-rework-p2-results-answer`) is wrong for a
Never on inserter, which the checks assumed off. It is in the owner's install-step review; one sentence fixes it.

## Change

- **A live sentence for the rule.** Under the mode choice, above the mode's fields, an "In words" line states the rule in
  plain words as it is edited ("On at ticks 12–20 and 80–95 of every 264 ticks."; "On while Electromagnetic science pack in
  the source ≥ 32 or the source is Output full. Once on, it stays on until …"). It updates on every change, before Save.
- **What reaches the blueprint, per mode.** Under the sentence, an "In the blueprint" line (copy below): the rule is not
  copied into the blueprint; the simulator follows it and the blueprint switches the inserter on in the ticks it moved items.
- **Clocked windows against the period.**
  - A period line: "Crafting cycle: 132 ticks. Clock period: 264 ticks (2 crafting cycles). From the clock on Results." (or
    "From your last check."; with neither, it says to run Check only or Generate).
  - A strip under the windows draws 0 to the rule's period with your windows as solid bars and, when Results are for this
    build, the clock's windows for this entity as outlined bars on a second labelled track.
  - **Default to the planned window.** Switching an entity to Clocked, when Results are for this build, fills the windows
    with that entity's wake windows in the clock on Results and "Repeat every" with the clock period. A "Use the clock's wake
    windows" button does the same at any time. Without Results the first window is empty, not 0–100.
  - "Repeat every" helper names the number: "Leave empty to repeat every crafting cycle (132 ticks)."
- **Inline checks that block Save.** End before start; outside the period; empty or non-whole ticks; a bad "Repeat every"; a
  condition with no item; a Conditional rule on a drill. Each shows under its field (`aria-invalid`, helper text). Save with
  problems keeps the dialog open, moves focus to the first problem and announces "Can't save yet: …" through the one polite
  region. One non-blocking warning: a "Repeat every" that does not fit a whole number of times into the clock period.
- **Templates ask, then confirm.** Only templates that fit the inserter's ends are listed. Choosing one opens an inline step
  with an item picker (preselected with the item the inserter moves), for "Latched output drain" an amount (default twice the
  stack size, so 32 at stack 16: the repo's sample), and "This replaces your 2 conditions." with **Replace conditions** and
  **Cancel**. Nothing changes until Replace. "Copy from another inserter" gets the same confirm step when the rule is not Auto.
- **Cleaner editor:** "Source"/"Destination" everywhere (the List row's words; the stored `SOURCE`/`SINK` are unchanged),
  sentence-case names, named groups, the heading only "Enable rule" (buttons outside it), drills without Conditional, the latch
  copy in glossary words.
- **Not changing:** the engine, the config schema and file format (a saved rule loads and exports byte-identically if you
  Save without editing), the chip text (`enableRuleLabel.ts`), the Diagram dialog's draft model (1.8), Fullscreen (kept,
  moved out of the heading), the five modes' names, Clear rule, the discard prompt.
