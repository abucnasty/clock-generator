# 0.21.0: trust the export

This is the plan for release 0.21.0: what it is for, its packages in order and what it leaves for later. It is kept while the release is in flight and dropped when 0.21.0 is released. Live status is on the Real Boy board, https://github.com/users/abucnasty/projects/2, item "0.21.0 · Trust the export"; this page does not follow every merge. The milestones and follow-ups it names are in [ROADMAP.md](../ROADMAP.md).

## What the release is for

What the sidecar exports and what the generator gives back should say what the build is, and what the game tests check should be what the generator makes. 0.21.0 marks a drop onto a belt that side-loads downstream, says when a filling output chest is why nothing holds, records a clock the owner built beside a generated one, gives Stupidfathobbit's cell 02 the export rate it is refused for, and checks that every game test is pinned to a clock the generator still makes.

The goals keep their order ([GOALS.md](../../GOALS.md)): goal 1, the clock meets its target exactly and recovers; goal 2, the fewest wake-ups. Model corrections are reported apart from search-only changes, and search-only changes keep every result identical. The time spent searching at generation does not grow ([working rules](../working-rules.md), rule 6).

Engine and UI are 0.21.0 and Sidecar the version after 0.20.0's (unless the owner sets another), since `0.21/sideload-drop` changes the export; each has one unreleased changelog entry.

## Packages, in order

Packages are named `0.21/<code>`. The numbering follows the board item.

### 1. Labels and marks in the result

`0.21/machine-labels` moved to 0.20.0 as `0.20/descriptions` and shipped there ([CHANGELOG.md](../../../CHANGELOG.md)).

**`0.21/sideload-drop`**, a drop onto a belt that side-loads downstream. On the owner's lithium plate build with a rocket silo as a buffer, two furnaces' output inserters drop onto underground entrances whose exits side-load onto the belt that carries the other furnaces' plates. The capture records one belt with room to spare, so the simulator gives those inserters more room than the game: the 7,560-tick clock is stable in the simulator and makes 9,440 to 9,600 of 10,080 a period in the game (the selected 1,080-tick clock holds). The owner's decision: the sidecar marks such a drop at export, as it marks a pickup from a side-loaded belt tile, and the result names it as a known limit. Done when the sidecar marks it, the generator shows the mark, and the owner's build shows it.

**`0.21/output-chest-fills`**, saying when a filling output chest is the cause. When nothing holds because a buffer output chest fills (issue #100's original config: 0 a second, 48 under the target), the result's why-not-stable message (#288) gives the rate but not the cause. The web form has warned about a filling chest since 0.17.0; the engine's result should name the cause too. Done when the result names a filling output chest as the reason, and the message is checked on that config.

### 2. Recording and pinning clocks

**`0.21/own-clock`**, recording a clock the owner built. The game harness records only a clock the generator made: it finds the clock's period from a decider described "Clock for…", and the recorder refuses a clock that counts from 0 ("Recorded clock value 0", `src/verification/recording.ts`). An owner-built clock on the logistic science inserter crafting build (a counter of 215, so a period of 216 ticks; one window pair for the ore and plate inserters and one for the gears; circuit and output inserters always on) had to be measured with a probe of its own: three copies on drained ore lines made 864 a period in each of 63 periods and recovered from an ore cut, an output block and a circuit cut. Done when the harness records a hand-built clock the same way as a generated one, and the owner's recorded run is a retained control beside a generated clock for the same build. It makes owner clocks comparable with generated ones directly.

**`0.21/game-test-pins`**, game tests pinned to clocks the generator no longer makes. Each game test runs a pinned clock, and CI runs no game tests, so a change that moves a selected clock leaves no failing test behind: #275 changed a selected clock and left a game test pinned to the old one. Add a unit test, which needs no Factorio, that every game test's pinned clock is one master still generates. Done when the test runs with the unit tests, passes on master and fails when a selected clock moves away from a game test's pin.

### 3. A real cell refused today

**`0.21/stupidfathobbit-cell02`**: Stupidfathobbit's cell 02 generates. `REAL_STUPIDFATHOBBIT_CELL02`, a processing-unit cell from the owner's save (#189), is refused in 0.19.0: one inserter puts electronic circuits onto a belt for the rest of a utility science design that the config does not include. Measure that belt's circuit draw from the owner's save, give the lane that export rate (the cell's scaffold is in the repository beside its config), and take the cell off the refusal list. Done when it generates, its result is pinned, and any verdict it gets is checked against its scaffold in the game.

### 4. The web app speaks the game's language

A UX review before 0.20.0 found parts of the web app that do not read the way the game does. 0.20.0 took the label and text fixes, the inventory grid and the drill's target; these follow.

**`0.21/machine-picker-style`**: the Machine picker in the recipe picker's style (groups, search, an icon grid), opened from the row's machine icon, with a recipe the machine cannot make shown on the row; and a crafting-speed hint from the machine and its quality, with modules and beacons in mind. Done when picking a machine feels like picking a recipe, and the hint is right on the samples.

**`0.21/wiring-reference`**: the install guide's wiring reference prints each combinator's first line as the game shows it, with the same entity icons (drills included), so a player can match the guide to the combinators they placed. Done when every combinator in a sample's blueprint has its line, drills included.

**`0.21/paste-preview`**: the paste preview's "can't be simplified" box only for exports with several copies, worded as information ("imported as one unit"); the chest list names its types (car, infinity chest); the duplicate line and the jargon go. Done on the owner's car, wagon and silo exports.

**`0.21/results-wording`**: the results view's older wording: "Belt: No belt" on a build with a belt (it means no belt pickups), 0 wake-ups beside a share of the period on, the recommended clock's first note read as a fault, the jargon of Details and assumptions, and how a decider can have more windows than swings. Done when a player new to the tool can read the car build's results without a question.
