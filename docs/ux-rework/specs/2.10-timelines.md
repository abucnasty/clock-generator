## Why it is wrong today

All numbers are WCAG relative-luminance contrast against the track the marks are drawn on. The track is
`action.hover` (8% white) over the Paper (`#232323` plus MUI's elevation-1 overlay = `#2e2e2e`), which paints as
**`#3f3f3f`** (the review's "about `#3f3f3f`").

- **C12, Disabled is invisible.** `COLOR_BLIND_PALETTE.darkGrey` `#585858` on `#3f3f3f` is **1.48:1** (needs 3:1 for a
  graphical object, WCAG 1.4.11). Two more fail on the same track and the review did not name them: Swing blue
  `#0072B2` is **2.03:1** and the Factorio strip's `full_output` vermillion `#D55E00` is **2.72:1**. Blocked
  `#CC79A7` is **3.44:1**, so it already passes on colour; what hides it is the width (next point).
- **C12, marks are 1 to 3 px.** `StateTransitionTimeline.tsx:125` and `:238` use `Math.max(width, 1)`. A narrow mark is
  also painted first-to-last in tick order, so the next transition overpaints most of it. The Transfer bars use
  `Math.max(widthPercent, 0.5)` (`TransferHistoryVisualization.tsx:67`): 0.5% of a 130px track is under 1px.
- **C11, items borrow the state colours.** `TransferHistoryVisualization.tsx:13-27` colours the nth item with
  `COLOR_BLIND_PALETTE_ALL[n]`: blue, orange, **yellow** (the "Waiting" colour), **green** (the "Active" colour),
  sky blue, vermillion, reddish purple, then **dark grey** (the invisible Disabled), light grey, white. The state chart
  sits directly below, with the same colours meaning states.
- **C11, the 6px Factorio strip has no legend** (eight colours, `colors.ts:136-145`).
- **C11, two detailed statuses share a swatch each**: Machine "Ingredient Shortage" and "No Fuel" are both yellow;
  Inserter "Target Full" and "Waiting For Sink" are both reddish purple (`colors.ts:40-41, 47-48`). In Detailed mode
  (a developer view) the legend shows two identical swatches.

## Change

- **A separate palette for items.** The Transfer chart colours items from six colours chosen to stay away from every
  state colour: `#E0298B` magenta, `#8BE3F9` pale cyan, `#E9C9C4` pale rose, `#873DF5` violet, `#8B92F9` periwinkle,
  `#BC884E` tan. No green, yellow, orange-state or grey. The first item gets magenta, and so on, in the existing
  alphabetical order; from the seventh item the colours repeat, and the legend says so in one caption (the row icons and
  the tooltip name the item either way).
- **A darker track, shared by both charts.** The track behind the marks, and the legend chips behind the swatches,
  become `#1b1b1b` (the review's number). Every colour the charts draw is then at least 3.2:1 on it, except Disabled.
- **Disabled grey `#707070`** (3.48:1) instead of `#585858`, in all four places it is used (the category map, the
  inserter map, the drill map and the Factorio strip). It stays clearly apart from Idle `#AAAAAA` by lightness alone
  (ΔE 20, so it does not rely on hue; contrast between the two is 2.13:1, so they read as two greys).
- **Every mark is drawn at least 3px wide**, in the state bar, the Factorio strip and the Transfer bars. Where marks
  are closer than 3px, the narrow ones are painted over the wide ones and **Blocked is painted last**, so the state a
  player debugs most is never the one covered.
- **A legend for the Factorio-state strip**: a second row under the existing legend, "Bottom strip: the state the game
  shows", with a swatch and the game's own name for each state that appears in the data.
- **Detailed mode: no shared swatches.** Machine "No Fuel" becomes orange `#E69F00` (the Factorio strip already uses it
  for `no_fuel`); Inserter "Waiting For Sink" becomes vermillion `#D55E00`. *This goes beyond the plan's wording (C11

- **Left alone (the plan and the owner):** zoom, merged rows, keyboard stepping, hover tooltips, the canvas having no
  accessible name (see Risks), filters, sort, the "Plan / Exported clock" toggle, the fuel chart, the diagram's entity
  colours (C18), and the ▲ markers and hatch that C12 suggests.

## The palettes: measured

Method (the numbers are here so the review can check the choice; the implementer does not recompute them): WCAG
relative luminance for contrast; CIEDE2000 on sRGB-to-Lab for ΔE; colour-blind simulation with the Machado et al.
(2009) matrices at severity 1.0 for deuteranopia, protanopia and tritanopia. ΔE of about 2 is a just-noticeable
difference; 10 or more is "clearly different" for marks this size; 20 or more is unmistakable.

### State colours on the new track `#1b1b1b` (and what they were on the old `#3f3f3f`)

| Colour | Used for | Old track | New track | Needs |
|---|---|---|---|---|
| green `#009E73` | Active, Working, Pickup | 3.08 | 5.03 | 3 |
| yellow `#F0E442` | Waiting, Ingredient Shortage | 7.96 | 13.03 | 3 |
| reddish purple `#CC79A7` | **Blocked**, Output Full, Target Full | **3.44** | **5.63** | 3 |
| **grey `#707070`** (was dark grey `#585858`) | **Disabled** | **1.48** | **3.48** | 3 |
| light grey `#AAAAAA` | Idle | 4.53 | 7.41 | 3 |
| blue `#0072B2` | Inserter Swing | 2.03 | 3.32 | 3 |
| sky blue `#56B4E9` | Drop Off, waiting_for_more_items | 4.56 | 7.46 | 3 |
| vermillion `#D55E00` | `full_output`; new: Inserter Waiting For Sink | 2.72 | 4.45 | 3 |
| orange `#E69F00` | `no_fuel`; new: Machine No Fuel | 4.68 | 7.65 | 3 |
| white `#FFFFFF` | unknown Factorio state, clock-window band | 10.53 | 17.22 | 3 |

Why a darker track rather than a lighter Disabled: a grey that reaches 3:1 on the old `#3f3f3f` would have to be about
`#898989`, which is only 1.5:1 from Idle `#AAAAAA`, so the two greys would merge. On `#1b1b1b` the Disabled grey needs only `#6a6a6a` (3.18); `#707070` is
the choice for margin. Blue, vermillion and green come out as a side effect.

Two checks on the new pairs: orange vs yellow ΔE 21.7 normal, 11.6 deuteranopia, 15.2 protanopia, 18.8 tritanopia;
vermillion vs reddish purple ΔE 37.0 normal, 34.0, 40.9, 13.9 tritanopia. Both pairs are in the same entity type's
legend and so are adjacent on a bar sometimes; the ΔE stays above 10 in every simulation.

The search went over HSL colours with hue outside 40 to 170 degrees (so no yellow or green), kept those at least 3.2:1
on the track and at least ΔE 12 (normal) and 5 (any simulation) from all ten state colours, then picked the six that
are farthest from each other in all four simulations. Honest limits:
- Against the state colours the worst case is ΔE 6.0 under deuteranopia (periwinkle vs sky blue). That is a "close but
  separable" pair that never carries one meaning: items appear only in the Transfer chart, states in the chart below,
  and every row's item icons name the item. The old palette had exact duplicates (ΔE 0).
- Two items are never confusable with each other: the closest pair is ΔE 14.0 or more in every simulation.
- Violet `#873DF5` (3.29) and magenta (3.99) are the dimmest. They pass 3:1 on the track and are the colours that fail
  first if the track is ever lightened past about `#222222`.
- More than six items: the colour repeats. A build with seven or more distinct transferred items is rare; if the
  screenshots show one, the caption (below) covers it. Eight colours were found (adding `#D5150B` and `#2DADB4`), but
  the red is too close to vermillion and the teal to green for a "separate from the states" claim.

2. **`utils/timelineGeometry.ts`** (new, no imports from the engine or React)
   ```ts
   /** The narrowest a mark is drawn, in CSS px (WCAG 1.4.11 needs the mark to be seen; the review asked for 3) */
   export const MIN_MARK_PX = 3

   export interface MarkSpan { x: number; width: number; narrow: boolean }

   /** Where a mark that starts at `tick` and lasts `durationTicks` goes on a track `trackWidth` px wide */
   export function markSpan(tick: number, durationTicks: number, totalDuration: number, trackWidth: number): MarkSpan

   /** Paint order: 0 wide marks, 1 narrow marks, 2 narrow marks of a state that must not be hidden. Paint 0 first. */
   export function paintLayer(span: MarkSpan, priority: boolean): 0 | 1 | 2
   ```
   `markSpan`: `natural = durationTicks / totalDuration * trackWidth`; `width = max(natural, MIN_MARK_PX)`, never more
   than `trackWidth`; `x = tick / totalDuration * trackWidth`, then clamped to `[0, trackWidth - width]` so a narrow mark
   at the right end stays inside the track; `narrow = natural < MIN_MARK_PX`. A `totalDuration <= 0` or
   `trackWidth <= 0` returns `{ x: 0, width: 0, narrow: false }` rather than NaN. `paintLayer`: `!span.narrow` is 0;
   narrow is 1, or 2 when `priority`.

`utils/timelineGeometry.test.ts` (`markSpan`, `paintLayer`, `MIN_MARK_PX`):
- A wide mark keeps its natural span: tick 50, 100 ticks of 1000 on 500px gives `x 25, width 50, narrow false`.
- A narrow mark is `MIN_MARK_PX` wide, `narrow` true, `x` unchanged: 1 tick of 1000 on 500px (0.5px) gives width 3.
- A zero-duration mark is 3px wide.
- A mark at the right end is clamped inside the track: tick 999, 1 tick, 1000 ticks on 500px gives `x 497, width 3`.
- Exactly 3px (6 ticks of 1000 on 500px) is not narrow.
- A track narrower than 3px gives `width <= trackWidth`, never negative `x`.
- `totalDuration` 0 or `trackWidth` 0 returns zeros, no NaN.
- `paintLayer`: wide is 0 whatever `priority`; narrow is 1; narrow with priority is 2. Sorting marks by `paintLayer`
