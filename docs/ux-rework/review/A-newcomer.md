# UX review: Designer A, the newcomer advocate

### 1. Gut reaction
I clicked a Reddit link promising a clock for my science build and landed on a bare form: "Recipe *", "Items per Second 1", "Copies 1", a machine with "Crafting Speed 1", and two grey buttons. Nothing tells me what a clock is, what I'll get or where to start. The two loudest controls are Import Config and Export Config, both for a config file I don't have. The brightest button on the screen is "Support me on Ko-fi". The mod that would make this easy is hidden in a ⋮ menu and never linked. If I did reach Results, I'd get a 110-word paragraph and a nine-column table about swings, windows and wake-ups, and no reason why the tool picked a clock with 177 wake-ups over a stable one with 0. On desktop I'd close the tab within 60 seconds. On my phone, where most Reddit clicks happen, I couldn't even get back to Configure.

### 2. Top 5 changes I'd make tomorrow

1. **A first-run screen with three ways in, and a link to the mod.** Today the first screen (02, 03) is a form with a title and no explanation. The only guidance ("Fill in the target, the machines and an inserter for every ingredient and output first.") sits at the very bottom, below the fold. Above the form, add one sentence on what the tool does ("Get a circuit clock that switches your inserters on only when needed, so your build makes exactly its target rate with fewer wake-ups"), then three buttons:
   - **Import from Factorio**: links the Clock Generator Sidecar mod and gives its 3 steps (Alt+E, drag over the build, Copy JSON).
   - **Try an example**: the repo already ships configs and scaffold blueprints for 9 science packs in `clock-generator/resources/config-samples/science/`, and the site exposes none of them.
   - **Build by hand.**

   This is where newcomers are lost, so nothing else matters until it is fixed.

2. **Never let an out-of-date blueprint be copied.** Importing a different build leaves the old clocks in place, and the workflow bar keeps offering them: "3 output swings per cycle · COPY BLUEPRINT" sits right beside "Changed since validation" (32, 34, 35). The Gleba nutrients build even shows the logistic-science transfer plan (35 part 3). Results are only cleared by Generate (`useSimulationWorker.ts:321`). The fix:
   - Disable Copy blueprint whenever the config differs from the generated one, with the tooltip "Your build changed. Generate again."
   - Put a banner on Results.
   - Clear results on Import, Paste and Reset.

   A player who pastes a clock made for a different build into a real factory will never trust the tool again.

3. **One Generate button, and disabled buttons that say what is missing.** Validate is disabled with no explanation, while the disabled Generate says "Validate the configuration first", which the player cannot do (04, 33; `WorkflowBar.tsx:133-141`). On the broken build seen from Results (33, 34), nothing on screen says what is wrong. The Missing Inserter alert only exists on Configure, and Import does not switch to Configure. The fix:
   - Fold Validate into Generate: Generate checks the build first and, on failure, stays on Configure and scrolls to the first problem.
   - Make the disabled tooltip name that problem ("Machine 1 has no inserter taking logistic-science-pack out").
   - Show a "2 problems" chip in the workflow bar on both views.

4. **Lead Results with "Your clock", the reason it was picked and how to install it.** The thing the player came for is on the third tab (Blueprint). Its only instruction is a tiny caption, "Copy this string and paste it in Factorio (Ctrl+V while in blueprint library)" (23). It never says that the blueprint is only combinators and that each must be wired to the inserters named in its description, and it never mentions Factorio 2.1. The fix:
   - Open Results on a summary card with a **Recommended** badge and one plain sentence on why this clock was chosen.
   - Turn the hidden "Belts do not move" switch into a visible question: "Your input belts are: moving / backed up and standing still". It is the reason the 0-wake-up clock was not picked.
   - Add numbered install steps under Copy blueprint.
   - Move the table and the Timelines, Insights and Log tabs below, as "Details".

5. **A plain-language copy pass with one word per idea.** The site uses hands, swings and transfers for one idea, and cycle, period and LCM for another. Clock names are engine internals ("Batched swings, non-moving belt: 4 output swings per cycle"). The worst paragraphs are the Potential Clocks intro (20), the Validation text (17), "Not searched" (20) and the bad-clipboard error (06). Rewrite them (wording in the table below), add a glossary popover, and rename the columns to what the player cares about: makes X/s, wake-ups (lower is better for UPS), and whether it works.

### 4. What I'd cut or hide
- **The Log tab and Debug Output**, including the copy shown before anything is generated. Put them behind `?debug` or a footer link.
- **Export Config as a top-level button.** Move it into ⋮ as "Save build file".
- **The separate Validate button.** Fold it into Generate. Move the Transfer Plan, "Exclude from LCM", LCM Override, Force Output Swings and Enable Fractional Swings into an expert section.
- **The Enable Control gear on every inserter and drill row.** Move it to an Advanced disclosure per row.
- **The "Exported clock / Plan" toggle** on the default Timelines tab.
- **Table columns** Clock period, Inserter windows, Clock-only output and Output swings. Keep them behind "Show details".
- **The Potential Clocks method paragraph** and the "Not searched" algorithm list. Use a "How clocks are tested" disclosure and a single "Search deeper" button.
- **Empty Chests and Mining Drills sections.** Replace them with one "+ Add chest / drill" row.
- **"About this build"** (the limits every clock works within) in Insights. Collapse it under "Why this clock".

### 5. What already works
- **The Missing Inserter Coverage alert.** It names the machine, the item and the direction, and offers one-click fixes ("Add to Belt 1", "Use Infinity Chest") (`MissingInserterAlert.tsx:23-60`). Every other error should follow this pattern; today it is just placed where players can't see it (finding 6).
- **The sticky workflow bar.** It shows the state ("Valid", "Changed since validation") and keeps Copy blueprint one click away from either view (18, 27). The structure is right; it only needs to stop offering a blueprint that is out of date.
- **The Insight headlines.** They are written as plain findings: "Machine 1 (logistic-science-pack) has 13 ticks to spare each clock period", "A full hand of logistic-science-pack takes 41.8 ticks to make" (22). That is the tone the whole Results page should take.

### 6. Open questions for the author
1. Who is the main audience: players who already wire their own clocks, or anyone who wants "a blueprint for my science build"? Most of this review assumes the second.
2. Is the Sidecar mod meant to be the main way in? If so, can the site link a mod-portal page, and can the mod copy a format that includes the target output?
3. Should the default pick favour a moving-belt clock? The samples README says a clock for a moving belt "has never been recorded" in the game, yet the default selection prefers moving-belt clocks over a 0-wake-up non-moving one (20). Should the site ask the belt question every time?
4. What exact enable condition must a player set on each inserter after wiring a combinator? The site needs to say it, and I couldn't confirm it from the UI.
5. Could the blueprint include the inserters (or a scaffold plus clock), so that pasting it over the build wires itself? That would remove the hardest manual step.
6. Is Validate separate only so that ingredients can be excluded from the LCM before generating? If so, can that move into an expert panel after Generate?
7. Does "Copies" change the blueprint at all, or only the rate per copy? The answer decides how much to explain it.
8. Is a phone layout in scope? Many Reddit visitors will see the site on a phone first and judge it there, even if they build on desktop.
9. How long does Generate take on a large build? The progress display (`GenerationProgressStatus`) was never captured, so I couldn't judge whether a newcomer would think it had hung.
