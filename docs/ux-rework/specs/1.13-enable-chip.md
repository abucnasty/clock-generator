# 1.13 Show the enable mode on the row
Findings: A23, B7, C24  ·  Implementer model: sonnet  ·  Branch: feat/ux-rework-p1-enable-chip

Line numbers are for `clock-generator-ui/src` at the head of `feat/ux-rework-p1` (`2da8d1d`, 0.9.0 code). Items 1.8, 1.9 and
1.11 change nearby lines; re-check the numbers against the phase branch before implementing (see "Overlap").

## What is wrong today

- **A23, B7.** Every inserter row (`components/InsertersForm.tsx:447-455`) and every drill row
  (`components/DrillsForm.tsx:247-255`) ends in the same bare `Settings` gear, in an `IconButton` with a tooltip, "Configure
  Enable Control". The only sign of the mode is that the gear turns the primary colour when the mode is not AUTO (line 451
  and line 251). With 20 rows you cannot tell CLOCKED from ALWAYS, CONDITIONAL or NEVER without opening each modal. The
  Diagram's node already shows the mode (`InserterFlowNode.tsx:55-58`).
- **A23.** A newcomer assumes the gear is a step they must do.
- **C24.** The gear is one of several unlabelled icons on a row. The review asked for a chip naming the mode.
- **Accessible name.** The gear's name comes from the tooltip ("Configure Enable Control"), the same on every row.
  Nothing says which inserter it belongs to, or what the rule is.

## Decisions

### 1. The chip is always there, and quiet for AUTO

SYNTHESIS #9 and A23 say "hide it until the mode isn't AUTO". The plan item says "stays quiet while the mode is AUTO and
opens the editor when clicked" and gives "Enable: Auto" as the AUTO label. Hiding the chip would also remove the only way
to open the rule editor for an AUTO row, which is how every rule starts. So: **the chip is on every row; for AUTO it is
quiet** (outlined, secondary text colour, no orange); **for any other mode it is the accent** (filled orange, the theme's
`primary`, which is the Factorio "selection or accent" colour in the owner's decision table). This is the plan's wording,
not a departure from it. A23's "per-row Advanced disclosure" is not done here (it would add a click for every rule); the
quiet chip meets "newcomers assume they must set it" by reading "Enable: Auto", not as a task. The orchestrator can veto
(the alternative is an icon-only quiet gear for AUTO and a chip for the rest, which keeps the 0.9.0 look but loses the word).

### 2. The label, as a pure function

New file `utils/enableRuleLabel.ts` (no React; imports `EnableControlMode` from `clock-generator/light` (a value, so not
from `clock-generator`), and `EnableControlOverride` / `RuleSet` types from `../hooks/useConfigForm`, and `isCondition`
from `../components/ruleSetUtils`, which is pure).

```ts
export const ENABLE_CHIP_MAX_CHARS = 32;

export interface EnableRuleDescription {
    mode: EnableControlMode;   // AUTO when there is no override
    chip: string;              // the text on the chip; never longer than ENABLE_CHIP_MAX_CHARS
    summary: string;           // everything, never cut; used by the tooltip and the accessible name
    quiet: boolean;            // mode === AUTO
}

export function describeEnableRule(
    override: EnableControlOverride | undefined,
    options?: { forcedAlways?: boolean },
): EnableRuleDescription;

/** "Enable rule for Inserter 3: Clocked 0–7 ticks. Edit" */
export function enableChipAriaLabel(entityLabel: string, description: EnableRuleDescription): string;

/** "Enable rule: Clocked 0–7 ticks. Click to edit." */
export function enableChipTooltip(description: EnableRuleDescription): string;
```

Every string the function writes is a named constant at the top of the file (`ENABLE_CHIP_PREFIX = 'Enable: '`, the five
mode names `Auto`/`Always`/`Never`/`Clocked`/`Conditional`, `RANGE_DASH = '–'` (U+2013 EN DASH, as in the plan's "0–7"),
the ` of ` before the period, the ` ticks` suffix, `+N more`, `latched`, `no ranges`, the forced-ALWAYS note, the ARIA
and tooltip templates, and the `…` ellipsis), so the 1.12 glossary pass changes words in one place.

**Labels, per mode** (`chip` / `summary`):

| Mode | `chip` | `summary` |
|---|---|---|
| none, or AUTO | `Enable: Auto` | `Auto` |
| ALWAYS | `Enable: Always` | `Always` |
| ALWAYS, `forcedAlways` | `Enable: Always` | `Always (set by Exclude from LCM)` |
| NEVER | `Enable: Never` | `Never` |
| CLOCKED, one range, no period | `Clocked 0–7` | `Clocked 0–7 ticks` |
| CLOCKED, one range, period 168 | `Clocked 1–2 of 168` | `Clocked 1–2 of 168 ticks` |
| CLOCKED, two ranges, period 112 | `Clocked 20–45, 74–89 of 112` | `Clocked 20–45, 74–89 of 112 ticks` |
| CLOCKED, `ranges: []` | `Clocked, no ranges` | `Clocked, no ranges` |
| CONDITIONAL, 1 condition | `Conditional: 1 rule` | same |
| CONDITIONAL, 4 conditions (nested) | `Conditional: 4 rules` | same |
| CONDITIONAL with a latch | `Conditional: 4 rules, latched` | same |

- **Rule count** is the number of leaf `Condition`s in `rule_set`, counted recursively (`isCondition`). Zero leaves reads
  `Conditional: no rules`. A condition's text (B7's "COND: sink < limit") is not attempted: nested rule sets have no short
  honest form. The full rule is one click away.
- **Ranges** print as stored (`start–end`, in ticks), in order, joined by `, `. They are not sorted or merged, and a range
  with `end <= start` (which Save would drop, but an imported file can carry) prints as stored. `period_duration_ticks`
  prints only when it is `> 0`. When absent, the period is the crafting cycle, which the form cannot know, so nothing is
  printed.
- **The truncation rule** (applies to `chip` only; `summary` is never cut). Build the CLOCKED chip by trying, in order, and
  taking the first whose length is `<= ENABLE_CHIP_MAX_CHARS`:
  1. all ranges and the period (`Clocked 20–45, 74–89 of 112`);
  2. all ranges, without the period;
  3. for k = n-1 down to 1: the first k ranges followed by ` +{n-k} more` (`Clocked 0–100, 150–250 +2 more`), no period;
  4. if even one range plus its suffix is too long, the one-range text cut to `MAX - 1` characters plus `…`.
  Every other mode's chip is also passed through the same final cut (a safety net; they are all under the limit today).
  32 is chosen so a two-range, three-digit CLOCKED rule with a period fits (`Clocked 120–145, 174–189 of 112` is 31
  characters), and a chip stays narrow enough to share a line with the filter slots at 1440px.
- **`forcedAlways`** is meaningful only with ALWAYS and is ignored for any other mode.

`enableChipAriaLabel` is `` `Enable rule for ${entityLabel}: ${summary}. Edit` `` and `enableChipTooltip` is
`` `Enable rule: ${summary}. Click to edit.` ``. The tick unit in `summary` is an addition to the plan's example
(`...Clocked 0–7. Edit`): the screen-reader user and the hover reader are told the numbers are ticks, and the chip text
stays short. The orchestrator can drop `ticks` by editing one constant.

### 3. Say when an ALWAYS was forced? Yes, in the tooltip and the accessible name, not in the chip text

1.8 adds `_forced_always?: true` on `InserterFormData` (set when "Exclude from LCM" writes an ALWAYS, cleared when the
rule is edited). Recommendation: **show it, but not on the chip**.

- "Enable: Always (excluded from LCM)" is 34 characters, over the limit, and "LCM" is the term the plan moves into the
  expert area only. The owner's glossary (1.12) may rename it. A two-part chip pushes the row's wrap point at 720px.
- A forced ALWAYS and a chosen ALWAYS are the same rule to the player editing the row; the difference matters when they
  ask "why did my inserter change?" or "what will Include do?". A tooltip answers that on hover, and the accessible name
  carries it for keyboard and screen-reader users, so nothing is colour- or hover-only.
- So `summary` gains `Always (set by Exclude from LCM)`, which becomes the tooltip text and the end of the ARIA label.
  The chip's colour and text are the same as a chosen ALWAYS.

Because 1.8 merges first, the field exists when this item is implemented. `InsertersForm` passes
`forcedAlways={inserter._forced_always}`. If 1.8 is not on the phase branch yet, the implementer leaves that prop out and
the rest still works (`forcedAlways` is optional); say so in the report. Drills have no such flag.

### 4. The chip component

New `components/EnableRuleChip.tsx`, exporting only the component (the `react-refresh` lint rule):

```tsx
interface EnableRuleChipProps {
    override: EnableControlOverride | undefined;
    entityLabel: string;          // "Inserter 3", "Drill 2": the same string the modal title uses
    forcedAlways?: boolean;
    onClick: () => void;
}
```

- `const description = describeEnableRule(override, { forcedAlways })`.
- MUI `Chip` with `size="small"` (24px high, which meets the WCAG 2.2 target-size minimum of 24px), `label={description.chip}`,
  `onClick` (MUI renders a keyboard-operable `role="button"`, Enter and Space), `aria-label={enableChipAriaLabel(entityLabel,
  description)}`.
- Quiet: `variant="outlined"`, `color="default"`, text `text.secondary`. Not quiet: `variant="filled"`, `color="primary"`
  (the theme's `#fca300` with MUI's computed dark contrast text, which is well above 4.5:1; the diagram's node chip does
  the same with explicit `#000`). No hard-coded `borderRadius` or font family: 2.7 makes chips square through the theme.
- Wrap in `<Tooltip title={enableChipTooltip(description)} describeChild>`. `describeChild` is needed so the tooltip does not
  replace the chip's own `aria-label` (it becomes the accessible description). It also doubles as the way to read a
  truncated chip in full.
- `sx={{ maxWidth: '100%' }}`: the label already ellipsizes inside MUI's `Chip`, so a very narrow row still shows one line.
- A visible focus style: only if the theme has none by then. `Chip`'s default focus change is a small background shift.
  Add `'&.Mui-focusVisible': { outline: '2px solid', outlineColor: 'primary.main', outlineOffset: 2 }` unless 1.11 has put a
  global 2px ring in the theme (then add nothing).

### 5. Where it goes in the row

Same slot as the gear: after the filter slots (`InsertersForm.tsx:437-445`), before the Delete button (line 457); in the
drill row after the machine select, before Delete (`DrillsForm.tsx:256`). The row is `display: flex; flexWrap: wrap`, so a
chip that is too wide for the line wraps to the next one like the other fields.

`entityLabel` is the string the row's modal already uses: `` `Inserter ${index + 1}` `` (`InsertersForm.tsx:477`) and
`` `Drill ${drill.id}` `` (`DrillsForm.tsx:286`). Compute it once per row (`const entityLabel = ...` inside the `.map`) and use
it for the chip. Leave the modal's `entityLabel` props as they are: 1.9 changes the inserter's to the stored id and this
item must not fight it (see "Overlap").

## Change

- The gear in every inserter row and drill row is replaced by a chip that names the enable mode: `Enable: Auto`,
  `Enable: Always`, `Enable: Never`, `Clocked 20–45, 74–89 of 112`, `Conditional: 2 rules, latched`.
- An AUTO row's chip is quiet (outlined, grey text), so a build with no custom rules reads as before. Any other mode is an
  orange chip, so overridden rows stand out in a long list.
- Clicking the chip, or pressing Enter or Space on it, opens the same enable-rule editor the gear opened. Nothing in the
  editor changes.
- The chip has an accessible name that says which entity and what rule ("Enable rule for Inserter 3: Clocked 0–7 ticks.
  Edit"); hovering it shows the full rule (and, for an ALWAYS set by Exclude from LCM, says so).
- Long CLOCKED rules shorten to `Clocked 0–100, 150–250 +2 more`; the tooltip and accessible name keep the whole rule.

## Risks and checkpoints

- **No checkpoint from `ORCHESTRATOR.md` is tripped.** No new dependency, no CI or `.claude` change, nothing the plan
  contradicts. The glossary (1.12) checkpoint is not opened here: the chip's words are named constants in one file so the
  owner's glossary can change them (`latched`, `Always (set by Exclude from LCM)`, `LCM`, `ticks`, `Enable:`); do not
  treat today's words as approved.
- **Choices beyond the plan's wording** (the orchestrator can veto each): (a) AUTO keeps a quiet chip instead of hiding
  (Decision 1); (b) `ticks` in the accessible name and tooltip (Decision 2); (c) the "set by Exclude from LCM" note lives in
  the tooltip and accessible name, not on the chip (Decision 3); (d) `Conditional: N rules` counts leaf conditions of
  `rule_set` only, not of the latch's release condition.
- **Mixed case.** The modal's radios and its "Copy from another inserter" menu use `ALWAYS`/`CLOCKED` in capitals; the chip
  uses `Always`/`Clocked`. 1.12 should settle one form. The diagram's node chip also still shows the raw mode.
- **Orange chips on every overridden row.** A build with many CLOCKED inserters (the shared samples have two; some builds
  have a dozen) will show many orange chips. That is the information B7 asked for, but if the UX audit finds it too
  loud, the fallback is `variant="outlined"` with `color="primary"` for the non-AUTO state, a one-line change.
- **`describeChild` and double reading.** With `describeChild`, a screen reader says the name and then the tooltip text,
  which repeats the summary. Accepted; 1.11 (which sets `describeChild` on tooltips) may refine it.
- **Overlap with items specced in parallel.** The row JSX in `InsertersForm.tsx` and `DrillsForm.tsx` is the shared ground, so
  1.13 cannot run alongside 1.9 or 1.11 (the three-at-once rule needs no common file); 1.3 (Undo snackbar: the delete
  buttons and `onRemove` at `InsertersForm.tsx:457`, `DrillsForm.tsx:256`) is nearby too.
  - **1.9** (renumber; chips show the id): changes `displayId={index + 1}` (`InsertersForm.tsx:232`, `DrillsForm.tsx:164`),
    and the strings `` `Inserter ${index + 1}` `` at lines 477 and 489. 1.13's `entityLabel` is a per-row constant, so 1.9
    changes it to `` `Inserter ${inserter.id}` `` in one spot, and the chip's accessible name follows. If 1.9 merges first,
    1.13 uses 1.9's label helper if it adds one, else the id. If 1.13 merges first, 1.9 must update `entityLabel` where it is
    computed, not the chip.
  - **1.11** (accessibility): names the Delete buttons (`aria-label="Delete inserter 7"`) in the same rows and sets
    `describeChild` on tooltips that replace names; it may add a global focus ring and 24px targets. 1.13's chip is already
    named, so 1.11 must not rename it, and drops 1.13's own focus style if its ring is global. Expect a textual merge
    conflict in these two files either way: whichever merges second rebases.
  - **1.8** (merged first): `_forced_always` on `InserterFormData`, and `enableControlDraft.ts` / `buildEnableControlOverride`,
