## Why it breaks today

- **Two `Snackbar`s exist in the whole app** (`grep Snackbar` over `src`), and both are trapped in a stacking context:
  - `ConfigImportExport.tsx:378-387`, bottom centre, rendered inside the `AppBar`. A fixed `AppBar` (z-index 1100) is a
    stacking context, and the footer (`App.tsx:512-553`, `position: sticky`, same z-index 1100, later in the DOM) paints
    over it. The bad-paste error and "Configuration imported successfully!" are cut in half and gone after 4 s
    (A14, B30, C6; shots 06, 09).
  - `WorkflowBar.tsx:113-122`, top centre ("Copied. {rateWarning}", 10 s). It sits in the workflow bar's `Paper`
    (`position: sticky`, z-index 1099, `WorkflowBar.tsx:72-77`), which is its own stacking context. The snackbar's own
    z-index 1400 only counts inside it, so the 1100 app bar paints over it, and at top centre it lands exactly on the
    app bar (C6, A14; unverified in the review). 1.2 replaces this with a `Portal` anchored bottom centre as a
    stop-gap, and says 1.5 deletes it.
- **The footer is the loudest thing on the page** (`App.tsx:512-553`): it is `position: sticky; bottom: 0` on every
  screen (46px of a dense tool, B30), and its "Support me on Ko-fi" is a filled orange `variant="contained"` button, the
  only saturated filled control on first visit while Generate is grey (A29, C3).
- **Other defects in the current snackbar code that the move should not carry over:**
  - Both `onClose` handlers ignore the `reason`, so any click anywhere on the page (MUI reason `clickaway`) closes the
    message. A "Copied. {warning}" message disappears the moment the player clicks anything else.
  - A new message while one is open only changes the text. MUI restarts the auto-hide timer only when `open` or
    `autoHideDuration` change, so the second message inherits what is left of the first one's 4 s.
  - Errors (the paste failure, the failed import) disappear after 4 s. The player cannot read them again.

## Decision: one app-root message host fed by a small context (`notify()`)

**Mechanism:** a `MessageProvider` at the top of the tree (in `main.tsx`, around `<App />`) owns one `useReducer`; any
component calls `const notify = useNotify()` and `notify({ severity, text, ... })`; a single `<MessageHost />` rendered
once in `App.tsx`, inside `ThemeProvider` but outside the `AppBar` and the footer, draws the current message in a
`Portal`.

Why this and not the alternatives:

1. **Context, not props.** `ConfigImportExport` and `WorkflowBar` are both deep in the header; 1.3's Undo needs `notify`
   in `App.tsx` (the `remove*` wrappers, `resetConfig`), in `ConfigImportExport` (Import, Paste, Reset) and possibly in
   the forms. `App.tsx` already passes ~12 props to `ConfigImportExport`. A context gives every caller one line.
2. **Provider in `main.tsx`, host in `App.tsx`.** `App` itself must be able to call `useNotify()` (1.3 does), so the
   provider has to be above `App`. The host has to be below `ThemeProvider` (`App.tsx:281`) so the snackbar gets the
   dark theme and Titillium. Hence two pieces.
3. **Two contexts, one for the stable functions and one for the current message.** `notify` and `dismiss` never change,
   so `App` (a very large component) and the header do not re-render when a message appears or goes. Only
   `MessageHost` subscribes to the state.
4. **Latest message wins, no queue.** A new `notify` replaces the open message at once. Reasons: the player should see
   the result of the thing they just did; Undo (1.3) restores the snapshot taken before the *last* destructive action,
   so an older Undo is already obsolete; and a queue would show "Configuration exported" for 4 s after the player has
   moved on. The reducer carries an `id` per message so a late dismissal from an older message cannot close a newer one.
5. **A reducer in `utils/` with no React**, so the rules (durations, replace, stale dismiss) are vitest-tested in Node.
6. **No new dependency.** `notistack` would add one, which is a checkpoint. MUI `Snackbar`, `Alert` and `Portal` are
   already installed and used.

## Change

- All messages appear **below the header** (below the workflow bar), top centre, drawn over the page content, above the
  footer, dialogs and everything else. At 390px, where the header wraps to two or three rows, the message still sits
  under the last row and never covers Configure/Results, Generate, Copy or the ⋮ menu.
- The two existing snackbars move to the host with the same wording and no behaviour change except what is listed
  here:
  - **Repeat messages restart the timer.** Exporting twice in a row shows the message for its full time again.
  - **A click elsewhere no longer dismisses a message.** It goes after its time, with Escape, or with its close button.
  - **Error messages stay until dismissed** (close button or Escape) or until a newer message replaces them. Success

  - **Hover or focus pauses the timer** (MUI already does this; keep it).

### The interface 1.3's Undo snackbar will use (do not implement 1.3 here)

`notify({ severity: 'info', text: 'Inserter 3 deleted.', durationMs: 10000, action: { label: 'Undo', onClick: restore } })`.
The host renders the action as a text button before the close button, and **closes the message after `onClick` runs**.
So 1.3 needs no change to the host, only calls. The reducer already allows `durationMs` to override the severity
default and `null` to mean "no timer". 1.3 should be implemented after this item merges (see Risks).

### Accessibility of messages, and how it coexists with 1.11's `role="status"`

- **Each message is announced once, by the host, through the `Alert`'s own role.** The host does not add an `aria-live`
  wrapper (that would nest live regions and double-announce).
  - `error` and `warning`: `role="alert"` (MUI's default; assertive). The player needs these now.
  - `success` and `info`: `role="status"` (polite).
  - Each message mounts fresh (`key={message.id}`), so every message is announced on insertion.
- **1.11 adds one persistent `role="status"` region in the workflow bar for check, generate and copy.** The two do not
  compete, by this rule, which 1.11's spec must follow:
  - The workflow-bar region announces **workflow state** that has no visual message of its own: "Checking…",
    "Check passed", "Generating…", "Generated N clocks", and "Blueprint copied" when the copy has **no** warning.
  - Anything raised through `notify()` is announced **only** by the host. So when a copy has a `rateWarning`, the host
    announces "Copied. {warning}" and the workflow-bar region stays silent for that copy.
  - Export, import and paste results (rows 1-6) are announced only by the host.
  - A transient success message from the host is the one other `role="status"` element in the page; it exists only
    while the message is open. That is not a second persistent region.
- The close button has an accessible name ("Close", MUI's default on `Alert`'s `onClose`; keep that name on the custom
  action version). The Undo action button's name is its label.
- **Escape closes the open message** (MUI's `Snackbar` listens on `document`). It also closes it when Escape was meant
  for a menu or dialog; that is acceptable because the message auto-hides anyway, and `MessageHost` must not
  `preventDefault` it.
- **Known limitation, for 1.3 and the orchestrator:** the portal sits at the end of `<body>`, so for a keyboard user the
  message's Undo button is the last tab stop after the footer. A keyboard-only player who resets by mistake has 10 s to
  Tab all the way there. This item does not solve it; the host already exposes `current.action`, so a one-level
  shortcut (for example Ctrl/Cmd+Z, while the Undo message is open and focus is not in a text field) can be added in 1.3
  without a history. Raise it when 1.3 is specced.
- Contrast: `Alert variant="filled"` for `warning` and `error`; the standard variant for `success` and `info`. Check the
  text contrast in the screenshots (filled warning is orange/white today; 1.14 retunes the warning palette later, so do
  not hard-code colours).

## Files

All under `clock-generator-ui/src` unless noted.

1. **`utils/messages.ts` (new, pure, no React).**
   - `type MessageSeverity = 'success' | 'info' | 'warning' | 'error'`.
   - `interface MessageAction { label: string; onClick: () => void }`.
   - `interface MessageInput { text: string; severity?: MessageSeverity; durationMs?: number | null; action?: MessageAction }`.
     `severity` defaults to `'info'`. `durationMs` defaults by severity (below); `null` means no timer.
   - `interface Message { id: number; text: string; severity: MessageSeverity; durationMs: number | null; action?: MessageAction }`.
   - `interface MessageState { current: Message | null }` and `const NO_MESSAGE: MessageState = { current: null }`.
   - `type MessageEvent = { type: 'notify'; id: number; message: MessageInput } | { type: 'dismiss'; id: number }`.
   - `const DEFAULT_DURATION_MS: Record<MessageSeverity, number | null> = { success: 6000, info: 6000, warning: 10000, error: null }`.
   - `messagesReducer(state, event): MessageState`:
     - `notify`: `current` becomes the new message (id from the event, defaults filled in). It always replaces.
     - `dismiss`: if `state.current?.id === event.id` return `NO_MESSAGE`; otherwise **return `state` itself**, so a
       late or repeated dismissal causes no re-render.
   - Export only what is used (knip): the reducer, `NO_MESSAGE`, and the types the hook/provider/host import.
   - Style: match `utils/rateWarning.ts` (named exports, 4-space indent, single quotes, semicolons).
2. **`utils/messages.test.ts` (new).** See Tests.
3. **`hooks/useMessages.ts` (new).** Holds the two contexts so no component file has to disable
   `react-refresh/only-export-components` (the existing `FullscreenContext.tsx` does; do not copy that).
   - `MessageActionsContext` (value `{ notify: (input: MessageInput) => number; dismiss: (id: number) => void }`, default
     a no-op pair, so a component rendered without a provider does not crash) and `MessageStateContext`
     (value `Message | null`, default `null`). Both are exported for `Messages.tsx`.
   - `useNotify(): (input: MessageInput) => number`, `useDismissMessage(): (id: number) => void`,
     `useCurrentMessage(): Message | null`.
4. **`components/Messages.tsx` (new).** Exports two components only.
   - `MessageProvider({ children })`: `useReducer(messagesReducer, NO_MESSAGE)`; `const nextId = useRef(0)`;
     `notify = useCallback((input) => { const id = ++nextId.current; dispatch({ type: 'notify', id, message: input }); return id; }, [])`;
     `dismiss = useCallback((id) => dispatch({ type: 'dismiss', id }), [])`; the actions value in `useMemo` over those
     two (stable). Provide `MessageActionsContext` and `MessageStateContext` (value `state.current`). `notify` must be
     called from event handlers or effects, never during render (StrictMode double-invokes render, which would burn ids).
   - `MessageHost()`: `const message = useCurrentMessage(); const dismiss = useDismissMessage();` returns `null` if
     there is no message (no exit animation; accepted). Otherwise:
     ```tsx
     <Portal>
       <Snackbar
         key={message.id}
         open
         autoHideDuration={message.durationMs}
         onClose={(_, reason) => { if (reason !== 'clickaway') dismiss(message.id); }}
         anchorOrigin={{ vertical: 'top', horizontal: 'center' }}
         sx={{
           top: { xs: 'calc(var(--app-header-height, 64px) + 8px)', sm: 'calc(var(--app-header-height, 64px) + 8px)' },
           width: { sm: 'max-content' },
           maxWidth: { sm: 'min(640px, calc(100vw - 16px))' },
         }}
       >
         <Alert ... />
       </Snackbar>
     </Portal>
     ```
     - Both `top` breakpoints are written out because MUI's `Snackbar` sets `top` at `xs` and again at `sm`.
       Fallback `64px` is the app bar alone, for the instant before `useStickyHeaderHeight` has measured.
     - `width: max-content` with a `maxWidth` is needed at `sm` and up: MUI centres the snackbar with `left: 50%;
       transform: translateX(-50%)`, which would otherwise shrink a long message to half the window (360px at 720px).
       Below `sm` MUI already stretches it between 8px margins.
     - `Alert`: `severity={message.severity}`, `variant={severity is 'warning' or 'error' ? 'filled' : 'standard'}`,
       `role={severity is 'error' or 'warning' ? 'alert' : 'status'}`, `elevation={6}` so it stands off the cards, and
       `sx={{ width: '100%', alignItems: 'center' }}`.
       - No action: `onClose={() => dismiss(message.id)}` (MUI draws the close button, named "Close").
       - With `message.action`: pass `action={<>…</>}` containing a `Button color="inherit" size="small"` (label from the
         action; its `onClick` calls `message.action.onClick()` and then `dismiss(message.id)`) followed by an
         `IconButton size="small" color="inherit" aria-label="Close"` with the `Close` icon from `@mui/icons-material`
         that calls `dismiss(message.id)`. (`Alert`'s `action` replaces the default close button.)
     - Do not wrap the message in an extra `aria-live` element.
     - `Portal` is MUI's (`@mui/material`). The host is rendered once, as a sibling of the root `Box`, so it is outside
       the `AppBar` and the footer; the portal makes sure no later wrapper with a `transform` or a z-index can trap it
       again.

## Tests

`clock-generator-ui` has vitest only, in Node, and no jsdom or testing-library. **Do not add either** (new dependency, a
lockfile change, a checkpoint). Only the reducer is tested.

New `utils/messages.test.ts` (vitest, same style as `utils/configForm/edits.test.ts`; no React):

- `notify` on empty state sets `current` with the given text and id, `severity` defaults to `'info'`.
- Default durations: `success` 6000, `info` 6000, `warning` 10000, `error` `null`.
- An explicit `durationMs` (for example 10000 on an `info` message with an `action`) overrides the default, and an
  explicit `null` on a `success` message gives no timer.
- The `action` is kept as given (same function reference).
- A second `notify` replaces the first (the earlier one is gone, the new id is current), including when the text is
  identical (the id differs, which is what restarts the timer in the host).
- `dismiss` with the current id gives `NO_MESSAGE`.
- `dismiss` with an older id (one that was replaced) returns the **same state object** (`toBe`), leaving the newer
  message open.
- `dismiss` on an empty state returns the same state object.

  "Ko-fi: quieter but still visible, an outlined or text button, in a footer that no longer sticks".
- **For the orchestrator to confirm, not owner questions:**
  - **Behaviour beyond the plan's wording:** errors persist until dismissed (6 s / 10 s for success / warning); clicks
    elsewhere no longer close a message; repeat messages restart their timer; "No items selected for import." is a
    warning, not an error. The plan only says where to render; A14 asks for paste failures that stay until dismissed,
