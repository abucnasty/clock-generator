## Why it is wrong today

- **The message is drawn over the page, with no timer.** `components/Messages.tsx:84-104` renders the one message in a
  `Portal` at the end of `<body>`, as a fixed `Snackbar` anchored top centre at `calc(var(--app-header-height) + 8px)`
  (`:99-104`). It sits over whatever is under the header. An Undo message has `durationMs: null`
  (`utils/undoSnapshot.ts:85`), so it stays there through Check, Generate and view switches until the next edit,
  Close or Escape (`hooks/useUndo.ts:41-47`).
  - 1440: "Build imported. Undo" covers the Items per Second label after an import, and the inserter's Destination field
    (`phase1-end/w1440/09-logistic-imported-above-fold-1440.png`; review B, shots 09, 34).
  - 720: it covers 36% of 2.4's "My belts stand still. Generate again" action and the end of the assumption sentence
    (`2.4/w720/06-results-moving-720.png`; `2.4/INDEX.md:214`, the one FAIL of 2.4's run, "the action is clickable").
  - 390: it covers the Target Output heading (`phase1-end/w390/04-logistic-imported-above-fold-390.png`) and the whole
    assumption sentence on Results, with only the action showing below it (`2.4/w390/06-results-moving-390.png`).
- **It is drawn over dialogs.** The portal is added to `<body>` after the dialog opened, and MUI's snackbar z-index
  (1400) is above the modal's (1300).
  - A failed-paste error ("Failed to paste: Clipboard does not contain valid JSON…") stays until closed
    (`utils/messages.ts:55`, `error: null`) and covers the title of the next "Confirm Import from Factorio" dialog
    (`phase1-end/w1440/07-paste-from-factorio-confirm-1440.png`) and the changelog (`…/w1440/08-changelog-dialog-1440.png`).
  - At 390, "Build imported. Undo" covers the changelog's text (ledger, "1.11 A → 1.5").
  - Over the fullscreen Diagram (`App.tsx:786-826`), the message sits under the page header's height, inside the
    canvas, and can cover a node (ledger, "2.11 → 1.5").
- **Keyboard users reach Undo last.** The portal is the last thing in `<body>`, after the footer, so Undo is the last
  Tab stop on the page. Ctrl/Cmd+Z (1.3) covers that, but the button itself is far away.
- **The offer outlives the run.** Because the offer survives Check only and Generate, a stray Ctrl/Cmd+Z on a non-text
  control (a clock radio, a button) long after an import still reverts the whole import (`hooks/useUndo.ts:140-148`), and
  "Build imported. Undo" stays up for a whole session in which the player never edits (reviews A6, B1).
- **2.4.11 passes only on a technicality.** A focused control is only "partly" covered, so `checkFocusNotObscured`
  passes (36% at 720), while the player cannot see or click most of it.

## Pick: put the message in the page's flow, in the sticky header under the workflow bar

**The message becomes a row of the `AppBar`, under the workflow bar (and its note and progress rows), instead of a
fixed layer over the page. In the fullscreen Diagram it goes in the dialog's title bar instead. In any other dialog it
stays where it is, in the header behind the modal. A message with no action (an error, a success, a warning, the "Build
restored" notice) closes when such a dialog opens, or when the action that raised an error starts again.**

What was weighed:

| | In the header's flow (picked) | Fixed, moved clear of the focused control | Fixed, bottom-left from 960px (review B) | Inline in the workflow bar's first row (review A) |
|---|---|---|---|---|
| Covers page content | Never: the header grows by the message's height | Yes, anything not focused (the 2.4 action is covered until it is focused) | Yes: the List's lower rows, the diagram's zoom controls (bottom-left), a dialog's buttons | Never |
| 2.4.11 (focus not obscured) | Holds by construction. The header's height already sets `scroll-padding-top` (`hooks/useStickyHeaderHeight.ts:16-21`), so keyboard focus and scripted scrolls stop below the message | Needs a watcher on every focus change and a second place to jump to | Needs `scroll-padding-bottom` while shown | Holds |
| 1.4.10 reflow at 390 | Wraps inside the header; no sideways scroll | Same as today | Same as today | Long messages ("Deleted Machine 2. Machines 3–4 are now 2–3. Inserters 1–2 have no Source now.", a rate warning) do not fit; the bar would wrap anyway |
| Layout shift | The page below moves down by one row when a message comes and back when it goes (see "Layout shift" below) | None | None | The bar's buttons move sideways under the pointer when it comes and goes: worse |
| Dialogs | Behind the modal, never over it. The fullscreen Diagram gets its own slot in its title bar | Over the dialog unless more rules are added | Over the dialog | Behind the modal |
| Keyboard reach of Undo | In the header: about 6–10 Tab stops from the top, before the page | Last Tab stop | Last Tab stop | In the header |

The header's flow is the only option that never covers anything, and it reuses what 1.2 and 1.11 already built: the
header's measured height and `scroll-padding-top`. The cost is the layout shift, which is bounded and comes almost always
from the player's own action.

**Why not close an Undo message when a dialog opens:** that would end the offer on something the owner's rule does not
list (an edit, another undoable action, Close, Escape, a check or generation starting). Behind a modal, the message loses nothing: it has no timer, it is back when the dialog closes, and
Ctrl/Cmd+Z is already ignored inside those dialogs (`utils/undoKeys.ts:35-38`, `hooks/useUndo.ts:145`). So while the offer
stands, Undo is always visible wherever Ctrl/Cmd+Z works.

**Why the fullscreen Diagram is different:** it covers the whole page, header included, and is a view of the build where
1.3 deliberately keeps Ctrl/Cmd+Z working (`data-fullscreen-diagram`, `App.tsx:792-793`). A delete from the diagram's
entity dialog must show its Undo there. The message goes in the title bar row, between "Flow Diagram" and Exit fullscreen,
so at 1440 and 720 it takes no height from the canvas (the compact message is shorter than the bar), and the canvas does
not resize and refit (`ConfigFlowDiagram.tsx:146-157` refits on any canvas size change). At 390 it takes a row of its own
under the title, so the canvas shrinks by that row and refits once; nothing is covered.

### Layout shift

- **When it comes:** after the player's own action (a delete, an import, a paste, Reset, a copy with a warning, Export, a
  failed import or paste). At scroll 0 the page moves down by the row (about 40px for one line). Further down the page,
  Chromium and Firefox keep the content in place by scroll anchoring and the taller header covers one more row; if that
  hides the focused control, the header's resize observer scrolls it back below the header (Files, `useStickyHeaderHeight`).
- **When it goes:** by Undo, Close, Escape, or pressing Check only or Generate (the player's action); by the timer of a timed message (success 6 s, the
  "Build restored" notice 8 s, a warning 10 s); or when an Undo offer is withdrawn by an edit. The last two are not the
  player's own click on the message. At scroll 0 the page moves up by the row. Nothing gets hidden when the header shrinks.
  This is accepted: it is one row, at the top, and the alternative (a fixed layer) is what covers content today.
- **Not done:** reserving the row while no message shows (a permanent 40–50px band in a dense tool) and animating the
  collapse (it still moves the page, only more slowly).

### Announcements

The in-page message now lives inside `#root`. While a dialog is open or closing, MUI hides `#root` with `aria-hidden`, so
an `Alert` with `role="alert"` inside it is never read. Two messages are raised exactly then: "No items selected for
import." (the confirm dialog is closing, `ConfigImportExport.tsx:248-252`) and "Copied. {rateWarning}" after the "Copy old
clock…" confirmation (`WorkflowBar.tsx:206-209`). And the message now moves between two slots (the header and the
fullscreen Diagram), which remounts it; a `role="alert"` remounted would be read a second time.

**So every message, errors and warnings included, is announced through the one polite region**, as success and info
messages already are, and the `Alert` gets `role="none"` whatever its severity. The region already handles a hidden
`#root` (`utils/announcer.ts:41-63`). Each message is announced once, when it is raised, never on a remount. This follows
the owner's "announcements go through the one polite region" (accepted by the orchestrator); it drops 1.5's assertive
`role="alert"` for errors and warnings (see Risks).

## Change

- A message shows as a compact row inside the sticky header, under the workflow bar, left-aligned with the
  Configure/Results toggle, as wide as its text up to the header's width. It wraps at 390. It never covers the page, the
  footer or a dialog, and it scrolls with nothing: it is always on screen while the header is.
- In the fullscreen Diagram, the message shows in the title bar, between "Flow Diagram" and Exit fullscreen (at 390, on
  its own row under them). When fullscreen opens or closes, the message moves between the two places and keeps its
  state (an Undo stays offered; it is not announced again).
- Behind any other dialog (the changelog, the paste confirmation, "Copy old clock…", the discard prompt, the rule and
  entity dialogs) the message stays in the header, under the modal. When the dialog closes it is still there, unless
  something below closed it.
- A message **without** an action (errors, successes, warnings, the "Build restored" notice) closes when a dialog other
  than the fullscreen Diagram opens (focus enters it from outside).
- "Failed to paste: …" closes as soon as Paste from Factorio starts again, and "Failed to import: …" as soon as a file is
  chosen to import again. A new message still replaces the one shown, as today.
- **The Undo offer ends when the player starts a check or a generation** (owner, 2026-10-14). The moment the player
  presses Check only (the workflow bar's or the swing plan's), Generate, Search deeper, or Results' "My belts … Generate
  again", and that press starts a check or a generation, the offer is withdrawn: the Undo message closes and Ctrl/Cmd+Z
  does nothing more. The "Build restored…" notice closes the same way (it asks for that press).
  - A press that starts nothing keeps the offer: Generate while something already runs (`wait`), Generate or Check only
    that only goes to the first problem or to the last check's error (`go-to-problem`, `go-to-check-error`,
    `show-problems`). Nothing was run, so nothing was accepted.
  - **An offer made while a check or generation is running** (the player deletes a row during "Checking…") stays: it
    came after the press. It ends at the next press that starts something. When Generate's check finishes and the
    generation starts by itself (`runChecked`'s `check-first` branch, `App.tsx:307-318`), that is not a press, so for
    plain Generate it does not end such an offer. Results' "My belts … Generate again" (`handleBeltAnswer`) and Search
    deeper with "keep it on" (`updateOverrides`) do end it at that moment: their deferred start edits the build, and an
    edit withdraws the offer as any edit does (an Undo would throw that edit away).
  - Checks that start without a press (the swing plan's re-check after an Exclude chip, `App.tsx:336-342`) follow an
    edit, which has already withdrawn the offer; they do not need the rule.
  - Nothing is announced when the offer goes this way: the player's own press caused it, and the region is about to say
    "Checking…" or "Generating clocks." (1.3's "Undo is no longer offered." stays for the editing-dialog case only.)
- Unchanged: one message at a time, latest wins; the durations; no click-away; hover or focus pauses a timer; Escape
  closes the message unless it was for a menu, list or dialog (`utils/undoKeys.ts:40-46`); Close and Undo return focus as
  1.3 built (`Messages.tsx:70-80`); Ctrl/Cmd+Z while the offer stands and every other Undo rule in `useUndo`; the texts;
  the `.MuiSnackbar-root` and `[data-message]` hooks the capture scripts and `useUndo` (`hooks/useUndo.ts:162`) use.

## Risks and checkpoints

- **No owner checkpoint is tripped**: no dependency, no CI, no version, no timer on Undo. The one change to the Undo
  rules (the offer ends when a check or generation starts) is the owner's own decision of 2026-10-14.
- **Errors and warnings are announced politely, once** (accepted: the owner's decision is one announcements region).
  They lose 1.5's `role="alert"`, so a screen reader reads them after what it is saying, not at once. Needed because the
  message now lives in `#root`, which a closing dialog hides, and remounts between two slots. Each is still read once,
  through the region, including when a dialog is closing.

  instead of pressing Undo. Undo of an import never brought the old clocks back (1.3), so little is lost. A screen
  reader user is not told the offer went (their own press caused it, and the run's own announcement follows); if the
  UX audit wants it, `UNDO_WITHDRAWN_MESSAGE` could be announced after the run's text, not instead of it.
