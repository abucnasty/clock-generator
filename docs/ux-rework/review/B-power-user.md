# UX review B: power-user interaction designer

Source paths are relative to `clock-generator-ui/src/` unless they start with `clock-generator/`. Screenshot numbers refer to `shots/INDEX.md`.

### 1. Gut reaction

The engine is serious and the results screen shows real depth, but the editor around it treats every session as a first visit. I can't trust what's on screen. After I import a different build, the bar still offers "COPY BLUEPRINT" for the old build's clock (32, 34, 35), and the Validation panel still shows the old build's transfer plan. Nothing can be undone. "Reset Configuration" sits one row under "Paste from Factorio" and fires without asking. The "#2" on a row is not the "Inserter 2" that Insights and the timelines are talking about. With 20 inserters I'd stop trusting the List view within an hour, keep the config in a text editor, and use the site only as a generate button.

### 2. Top 5 changes I'd make tomorrow

1. **Tie results to the config that produced them.** Today, importing, pasting or editing leaves the previous build's clocks, transfer plan and a live Copy blueprint button in place (32, 34, 35; `App.tsx:262-264`; `useSimulationWorker.ts:312-327` only clears results on Generate; `WorkflowBar.tsx:95-124`). Keep the config hash with each generation. When the current config differs, put an amber banner across Results: "These clocks are for logistic-science-pack at 240/s as generated at 14:02. The build has changed since. Generate again." Turn Copy into "Copy old clock…", which asks for confirmation first. Import, Paste and Reset should clear results and validation outright. A wrong blueprint pasted into a megabase is the worst outcome this tool can produce, and today it's one click away.

2. **Add a safety net: undo, confirmations and snapshots.** There is no undo anywhere (no matches for undo in `src/`). Reset Configuration wipes localStorage immediately (`usePersistedConfigForm.ts:197-200`) and sits directly under Paste from Factorio (05; `ConfigImportExport.tsx:355-366`). Import Config replaces everything without asking (`ConfigImportExport.tsx:98-113`). Row deletes are single unlabelled icons. In the diagram, Backspace on a selected edge deletes the whole inserter (`ConfigFlowDiagram.tsx:190-207, 258-272`). The change: an in-memory history with Ctrl+Z / Ctrl+Shift+Z, plus an "Undo" action on every destructive snackbar ("Inserter 7 deleted · Undo", "Configuration replaced by import · Undo"). Move Reset behind a divider, in red, with a confirm that names the build. Keep the last 5 configs in localStorage. Pros make big edits fast, and they need a cheap way back.

3. **One identity per entity, the same everywhere.** The row chip is the row's position (`SortableList.tsx:126`, `InsertersForm.tsx:232`), and so is the enable-control modal title (`InsertersForm.tsx:477, 489`). The pickers, diagram, Insights, Fuel and timelines all use the stored id (`InserterConfigPanel.tsx:196, 308`; `FuelPanel.tsx:17`; `utils/buildFlowGraph.ts:124`). Removed ids are retired (`utils/configForm/edits.ts:27-31`), so after one delete "Inserter 3" in Insights is row "#2". Dragging renumbers every id (`edits.ts:33-48`), so last run's "Inserter 5" is now some other inserter. The change: show the id in the chip, stop reassigning ids on reorder (or remove drag reorder), allow an optional name per entity, and use one label format everywhere. Debugging a 20-inserter build means mapping "Inserter 14 is woken 68 times a minute" to a row, and today that mapping is wrong.

4. **Merge Validate into Generate and stop moving the page.** Generate needs a separate Validate first. Validate switches to Configure and scrolls to the bottom panel (`App.tsx:198-203`). Any edit disables Generate, even toggling "Search for fewer wake-ups" (`App.tsx:192-195`). Nothing survives a reload: validation, results and your selected clock all live only in hook state. So each tweak costs: Configure → find the row → edit → Validate (yanked to the bottom) → Generate → re-pick the clock you were studying (`useSimulationWorker.ts:325` resets the pick). The change: Generate validates first and stops inline on errors. Keep Validate as a secondary "Check only" action that doesn't scroll. Keep the last results and selection per config hash in IndexedDB. Iteration speed is the whole job for this user.

5. **Make Potential Clocks a real comparison table.** The table has no "Recommended" marker and no per-row reason. The selection rule is a five-line paragraph (`ClockAlternativesPanel.tsx:84-92`). In 19/20 the tool selects a stable clock with 177 wake-ups over a stable "2 output swings per cycle" with **0**, and why is only in prose. The units are mixed: "Rate achieved" is the total over 11 copies, "Clock-only output 96 / 96" is per copy per period, and "Wake-ups" is per copy, and no header says which. Showing unstable clocks inserts them mid-table (25). The change: add a "Recommended" badge, a "Not picked because" column ("non-moving belt", "more wake-ups than #3", "no recovery"), sortable columns, units in every header ("/copy", "total"), unstable rows grouped at the bottom, and the paragraph collapsed to one line plus "How clocks are chosen". This table is where the expert makes the actual decision.

### 4. What I'd cut or hide

- **The five-line Potential Clocks paragraph and the three-line Validation paragraph** on the default path. Cut each to one line with a "How this works" disclosure (`ClockAlternativesPanel.tsx:84-92`, `ValidationPanel.tsx:48-52`).
- **Validate as a required step.** Fold it into Generate and keep "Check only" as a secondary action.
- **"Exclude from LCM" chips in the Validation panel.** They mutate inserter rules (#5). Move them into Advanced Overrides with an explicit warning.
- **Drag reorder**, unless order means something to the engine. It renumbers every id and breaks identity (#4).
- **Insights prose expanded by default.** Collapse it to titles plus tables.
- **The Log tab** unless debug logging is on. Move the debug toggles into a settings menu.
- **The Diagram as an equal "alternate editor".** Until it matches the List feature for feature, demote it to a read-mostly map that opens the same row editor.
- **The sticky Ko-fi footer.** Keep it, but not sticky.
- **The Fullscreen button on the enable-control modal.** Make the modal large enough instead.
- **The "Latched Output Drain" template's magic 32.**

### 5. What already works

- The **Exported clock / Plan** toggle, together with timeline hover showing tick, duration and transition reason and the clock-window overlay. That is the right primitive for debugging "why does the clock drift" (20, 21; `ResultsWorkspace.tsx:126-145`, `StateTransitionTimeline.tsx:170-190`).
- **Honesty about what wasn't tried.** The "Not searched: …" notice and the Status tooltip ("N clock start phase(s) simulated… repeats every N periods") tell an expert exactly how far to trust a verdict (19; `ClockAlternativesPanel.tsx:31-47, 215-221`).
- **Inferred filters with an AUTO badge**, and machine facts inline in the row (35, 10). Derived and explicit values are visibly different, which is what a pro needs.

### 6. Open questions for the author

1. Is the moving-belt-first selection policy a per-build fact or a player preference? If most experts run backed-up belts, "Belts do not move" belongs in a user-level default, not buried per config.
2. Does item order or id order mean anything to the engine or the sidecar mapping? If not, can ids become permanent and drag reorder go away?
3. Is one config per browser intentional, or do players keep several builds? That decides whether a build library is worth L effort.
4. Do CONDITIONAL and CLOCKED overrides reach the blueprint, or do they only shape the planning simulation? The modal should say which.
5. How long does "Search for fewer wake-ups" take on a 10-machine, 30-inserter build? That decides how urgent cancel, ETA and result caching are.
6. Is "Items per Second" meant as the total over all copies? Is per-copy wake-ups the number players compare, or should the table show the total?
7. Roughly what share of sessions start from Paste from Factorio? If most do, Paste should be a primary app-bar button, not a ⋮ item next to Reset.
8. Is the Diagram meant to reach parity and replace the List, or stay a viewer? Two half-editors over one model cost more than one good one.
