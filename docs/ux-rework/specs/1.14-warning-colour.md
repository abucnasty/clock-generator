# 1.14 A warning colour that isn't the brand orange
Findings: C4  ·  Implementer model: opus (moved up: 7 files)  ·  Branch: feat/ux-rework-p1-warning-colour

Line numbers are for `clock-generator-ui/src` at the head of `feat/ux-rework-p1` (commit 2da8d1d, 0.9.0 code). **This
item must be implemented after 1.1 and 1.2 have merged** (it edits `WorkflowBar.tsx` and `App.tsx`, which both of them
rewrite, and it styles the warning uses they add). Re-grep every line number below on the phase branch before starting;
the `WorkflowBar.tsx` and `App.tsx` ones will have moved. It also shares those two files with 1.4 and 1.5, so do not run
it at the same time as 1.4 or 1.5.

## Why it is wrong today

- `App.tsx:43-64` (`darkTheme`) sets `primary` to the brand orange `#fca300` and leaves `palette.warning` alone, so MUI's
  dark-mode default `#ffa726` is used. The two differ by CIEDE2000 **1.7**: the eye cannot tell them apart.
- So everything the site marks as a warning looks like an ordinary orange control. The two cases the review names:
  "Changed since validation" (`WorkflowBar.tsx:12`, an outlined chip beside the outlined orange Validate button) and
  Copy blueprint when the clock misses the target rate (`WorkflowBar.tsx:107`, `color="warning"` on a button that is
  `color="primary"` the rest of the time). The player cannot tell "this clock is wrong" from "this is the button".
- `warning.main` is also used as a stand-in for "drill" in two timeline labels. Changing the palette would turn those
  yellow (and make them read as warnings), so they are pinned (see Files, 8 and 9).

## Change

- **A real warning colour.** `palette.warning.main` becomes `#ffe14d` (a lemon yellow) with black text on it. Every
  `warning` Alert, Chip and Button on the site picks it up through the theme, with no per-component colour.
- **Filled, with a ⚠ icon, for the two things the review names.**
  - The "Changed since validation" chip is filled yellow with a ⚠ icon and black text.
  - The Copy button is a filled yellow button with a ⚠ icon whenever it warns: the clock is below the target rate, or
    has another warning (`rateWarning`), or (after 1.1) the results are stale. Black text. Otherwise it is unchanged
    (outlined orange, with the copy icon).
- **The label says what is wrong.** A below-target clock's button reads "Copy blueprint (192/s, below target)", with the
  clock's own rate. Precedence, from 1.1: when the results are stale the button reads "Copy old clock…" (stale wins over
  below target); the "Copy blueprint (192/s, below target)" label applies only when not stale. Once copied, it reads
  "Copied" as today.
- **Not changed:** the meaning of any warning (which clocks warn, the tooltip, the "Copied. {rateWarning}" snackbar's
  text), the green/red/blue palette, and the brand orange.

## The colour: contrast, and which variants are AA-safe

Computed (WCAG relative luminance, sRGB) for `#ffe14d`; the surfaces are the ones the theme produces
(`background.paper` `#232323`, MUI's dark-mode elevation overlay for Paper, the page `#404040`). The implementer does not
need to recompute these; the numbers are here so the review can check the choice.

| Pair | Ratio | Needs | Verdict |
|---|---|---|---|
| Black `#000` text on the yellow fill (filled Button, filled Chip) | **16.1** | 4.5 | Pass |
| MUI's own `rgba(0,0,0,0.87)` on the fill (what `getContrastText` gives the filled Alert) | 12.9 | 4.5 | Pass |
| Black text on the contained button's hover colour `warning.dark` `#ccb43d` | 8.7 | 4.5 | Pass |
| Yellow fill against the paper `#232323` | 12.1 | 3 (1.4.11) | Pass |
| Yellow fill against the workflow bar (elevation 2, `#323232`) | 9.9 | 3 | Pass |
| Yellow fill against the app bar (elevation 4 on grey 900, `#363636`; 1.2 puts the workflow bar there) | 9.3 | 3 | Pass |
| Yellow fill against the page `#404040` | 8.0 | 3 | Pass |
| **Outlined or text variant**: yellow text on paper, on `#2e2e2e`, `#323232`, `#363636` | 12.1, 10.4, 9.9, 9.3 | 4.5 | Pass |
| Outlined or text variant: yellow text on the page `#404040` | 8.0 | 4.5 | Pass |
| Outlined variant, hover background (4% yellow) behind the text | 7.2 to 11.0 | 4.5 | Pass |
| Outlined variant's border (MUI draws it at 50% alpha) on paper / `#323232` / `#404040` | 4.1 / 3.7 / 3.3 | 3 | Pass |
| Outlined variant, in a Dialog (`#474747`, as in 1.1's confirm button): text / 50% border | 7.1 / **3.05** | 4.5 / 3 | Pass, the border only just. The label carries the control, so this is fine, but do not make the dialog's surface any lighter |
| Standard Alert (dark mode): MUI's text `#fff5c5` on its tinted background `#19170b` | 16.4 | 4.5 | Pass |
| Standard Alert icon (`warning.main`) on that background | 13.8 | 3 | Pass |
| Filled Alert (the "Copied. {rateWarning}" snackbar): MUI uses `warning.dark` `#ccb43d` as the background in dark mode, with `rgba(0,0,0,0.87)` text | 8.7 | 4.5 | Pass |
| SVG marks drawn in `warning.main` (`SwingComparison`) on paper | 12.1 | 3 | Pass |

**Every variant (filled, outlined, text, Chip, standard and filled Alert) is AA-safe**, so there is nothing to work
around and no variant needs a second colour. If a future change lightens a surface past `#4a4a4a`, the outlined
border and the Dialog's 3.05 are what fail first: switch that control to the filled variant.

**Apart from the brand orange.** CIEDE2000 between `#ffe14d` and the brand `#fca300` is **19.8** (it was 1.7 for
`#ffa726`). It is 30.7 from the secondary green `#5eb664` and 51.1 from the error red. Simulated for deuteranopia and
protanopia the distance from the brand orange falls to 9.4 and 12.8: still separable, but not enough to carry the
meaning, which is why a warning also gets (1) a ⚠ icon, (2) a filled shape where the review asks for one, and (3) words
in the label or text. The colour is never the only cue. Two things to know about, neither a blocker:
- Yellow on yellow: the focus ring planned in 1.11 is `#fca300`, which is only 1.55:1 against the yellow fill. 1.11 must
  draw the ring with an offset (outside the button, on the dark surface) rather than directly on the fill; note it in
  the PR so 1.11 sees it.
- The timeline "Waiting" colour (`COLOR_BLIND_PALETTE.yellow` `#F0E442`, `colors.ts`) is almost the same hue as the new
  warning (ΔE 4.5). They never share a chart as meanings, so this is left to 2.10 (item colours vs state colours).

3. **`utils/rateWarning.ts`** (the file `rateWarningOf` lives in: it is already "what to tell whoever copies the blueprint")
   - Move `figure` (`:36`, `(rate) => Number(rate.toFixed(2)).toString()`) to module level and use it from `clockWarningOf`
     and the new function, so "192" and "12.5" print one way.
   - Add `export const COPY_BLUEPRINT_LABEL = 'Copy blueprint'` and `export const COPY_OLD_CLOCK_LABEL = 'Copy old clock…'`
     only if another file imports them (knip rejects unused exports). If 1.1 left the stale text inline in
     `WorkflowBar.tsx` and `BlueprintOutput.tsx`, import `COPY_OLD_CLOCK_LABEL` in both so the string has one definition;
     if not, keep them as plain consts.
   - Add the pure function

     ```ts
     export function copyBlueprintLabelOf(
         alternative: Pick<ClockAlternativeView, 'assessment' | 'ranking'> | undefined,
         stale: boolean,
     ): string
     ```

     1. `stale` is `true` returns "Copy old clock…".
     2. `alternative` is `undefined` returns "Copy blueprint".
     3. `!alternative.ranking.meets_target_rate && alternative.ranking.rate_off_target <= -MIN_SHORTFALL` returns
        `Copy blueprint (${figure(alternative.assessment.items_per_second)}/s, below target)`.
        `MIN_SHORTFALL = 0.005`, a module constant with a comment: a shortfall smaller than that prints as the target
        itself at two decimals ("240/s, below target" would read as nonsense). `items_per_second` is the rate the clock
        runs at (`rankingOf` in `clock-generator/src/crafting/rank.ts:47` derives `rate_off_target` from it), so
        `figure(items_per_second)` is the "192" of the plan's example.
     4. Anything else returns "Copy blueprint".

     Why only the below-target case gets words: the plan asks for that one label. The other warnings (the clock does not
     survive backpressure loss, a deadlock risk, an unstable clock at the target rate) keep "Copy blueprint" and are shown
     by the yellow fill, the ⚠ icon and the tooltip (and the "Copied. …" snackbar). See Risks for the follow-up.

### Icons (`npm run check:icons`)

`scripts/check-icons.mjs` and `scripts/icon-names.mjs` are about the **Factorio item icons** in `public/icons/*.png`
(`FactorioIcon`): they fail when the page draws a game icon that is missing, or `public/icons` holds a file no name asks
for. They never look at MUI icons, so the ⚠ needs no PNG and no change to `public/icons`. Use the MUI component
`Warning` from `@mui/icons-material` (a named import, like `Check` and `ContentCopy` on `WorkflowBar.tsx:1`; the package
is `^7.3.6` and `Warning.js` exists). Do **not** type the character "⚠": the site font (Titillium Web) has no glyph for
it, so it falls back to a coloured emoji in some browsers. The one thing to watch is `icon-names.mjs`'s scan of string
literals in `src` that equal a game item name: none of the new strings does ("Copy blueprint", "below target", ids
`warning`/`contained` are not game names); run `npm run check:icons` to confirm.

## Tests
New file `clock-generator-ui/src/utils/rateWarning.test.ts` (vitest, Node, no React; same style as
`utils/configForm/edits.test.ts`). There is no test file for `rateWarning.ts` today. Build the argument with a small

to the `Pick<…>` type (the full `ClockAssessment`/`ClockRanking` are not needed).

For `copyBlueprintLabelOf`:
- Below target: 192 of 240 (`items_per_second: 192`, `rate_off_target: -48`, `meets_target_rate: false`) and not stale
  gives "Copy blueprint (192/s, below target)".
- The rate prints like the warning sentence: 12.5 gives "12.5/s", 0.333333 gives "0.33/s", 240 gives "240/s".
- Stale wins: the same below-target clock with `stale = true` gives "Copy old clock…".
- Stale with `undefined` gives "Copy old clock…" (a stale view with no selected clock still says it).
- Not stale with `undefined` gives "Copy blueprint".
- A clock that meets the target (`meets_target_rate: true`, `rate_off_target: 0`) gives "Copy blueprint".
- Above the target (`rate_off_target: 12`, `meets_target_rate: false`) gives "Copy blueprint" (it is not below).
- Unstable at the target rate (`meets_target_rate: false`, `rate_off_target: 0`) gives "Copy blueprint".
- The shortfall threshold: `rate_off_target: -0.004` gives "Copy blueprint"; `-0.01` (rate 239.99) gives
  "Copy blueprint (239.99/s, below target)".
- It is consistent with `rateWarningOf`: for the 192-of-240 clock `rateWarningOf` (given a full alternative) is non-null
  and `copyBlueprintLabelOf` contains "below target"; for one that meets the target both are plain. (Only if building
  the full `Pick` for `rateWarningOf` is cheap; skip otherwise.)

Not tested, by the repo's setup (no jsdom or testing-library; do not add them): the theme values, the chip, the button
