### C1 reproduction and consequence

Import a valid build with `sink.drop`, switch to Diagram, open that destination belt, change its Belt Type or lane ingredient/stack size, and press Save. The dialog accepts a local draft and enables its footer. `updateBelt` then returns the previous whole config, and the dialog closes unconditionally. Reopening shows the old value with no explanation. A simultaneous otherwise allowed strategy/consumption edit is also lost because the guard rejects the whole update. This is introduced by applying the new refusal in the shared edit function without reconciling the existing dialog consumer. It violates the specified clear refusal/recoverable-edit boundary and is the reason for FIX.

The native geometry capture currently exercises the List belt/inserter controls, duplication and selective Paste (`docs/ux-rework/capture/compatibility-acceptance.mjs:55–56`); that pass does not exercise the diagram belt save or connection refusal. The passing counts therefore do not disprove C1/C2.
