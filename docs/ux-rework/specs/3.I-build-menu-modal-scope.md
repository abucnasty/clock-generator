# 3.I Isolate the build menu from background controls

Findings: native Phase 3 menu-scope diagnosis; closes existing 3.4 build-library accessibility behavior under the approved full WCAG 2.2 AA requirement. Bundle with 3.G/3.H on `feat/ux-rework-p3-shared-announcement`. No new feature or owner decision.

## Problem and evidence

The build menu is a MUI modal with a viewport backdrop, but its portal container is the nearest header. MUI hides siblings inside that container, leaving the main view exposed to assistive technology behind the modal. At 390×844 and actual scrollY1855, default axe reports the background machine-section Select button as partially obscured. Every sampled pointer point hits the menu backdrop. Waiting for finite modal animations reproduces the same failure; this is not an observation-framing correction.

Preserve `/tmp/ux-phase3-3gh-r8r-switcher-390` (110 PASS / 1 FAIL / 0 failed steps) and `/tmp/ux-phase3-menu-rest-diagnostic-390` (145 PASS / 2 FAIL / 0 failed steps).
