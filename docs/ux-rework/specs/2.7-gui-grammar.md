## What is wrong today

- **C3, hierarchy.** The loudest control is meant to be the next step. 1.5 already makes Ko-fi quiet. What is left in
  `WorkflowBar.tsx` (Phase 1 shape): Generate is the one `variant="contained" color="secondary"` button and stays filled
  after it has run; Copy blueprint is `variant="outlined" color="primary"` (1.14 makes it filled yellow with a warning
  icon when it warns). Nothing decides which single button is filled for the state the player is in.
- **C28, three confirm colours and pill chips.** Confirm is green in Generate, "Import Selected"
  (`ConfigImportExport.tsx`, `color="secondary"`) and the chest-filter popover's "Confirm", but orange in
  `EnableControlModal.tsx` Save (`color="primary"`) and, since 1.8, the footer Save in `InserterConfigPanel.tsx`
  (`variant="contained"`, default primary). MUI chips are 16px-radius pills in a site whose `shape.borderRadius` is 0.
  Green is also used as a decoration: the "excluded" chip in `TransferPlanPanel.tsx` (`color="secondary"`), the
  "limit" chip in `MachineFactsAccordion.tsx`, the AUTO badge in the filter slots.
- **C16, one help icon, four meanings.** Blue filled `Info` buttons in `MachinesForm.tsx`, `BeltsForm.tsx` and
  `DrillsForm.tsx` (`color="info"`, the only blue in the UI); a grey outlined `InfoOutlined` hover tooltip in
  `ClockAlternativesPanel.tsx` (1.11 makes it a click popover, `InfoPopoverButton`); `HelpOutline` in
  `ChestsForm.tsx` (opens a dialog); and an orange outlined `InfoOutlined` in `ConfigFlowDiagram.tsx` that is not help
  at all but the "show machine facts" toggle.
- **C23, Configure has no rhythm.** In the List view the order is Target, a floating List/Diagram toggle, then five
  equal `Paper` cards (Machines, Inserters, Belts, Chests, Drills) and Advanced, Validation. An empty Chests card
  is full-size; Mining Drills is a full card with an Enabled switch, a productivity field and an empty-state sentence.
  The toggle belongs to no card.
- **C24, inserter rows.** `InsertersForm.tsx` rows are a wrapping flex row: Source and Destination are fixed
  `minWidth: 250` and truncate while the row has empty space on the right; `FilterSlotSelector` always draws five
  slots (four empty); the delete button is a full-saturation red icon on every row, the loudest thing in the card.
- **Contrast, found while measuring for this item** (all Phase 1 baseline, see the token section for numbers): the
  green button's hover colour with black text is 3.98:1; error-red text fails on cards, the workflow bar and dialogs
  (4.40, 3.96, 3.00); MUI's input outline, outlined-chip border and switch track are 2.1 to 2.6:1 against 3:1;
  an orange "Undo" on MUI's near-white snackbar is 1.96:1; the empty filter slot's border is 1.46:1 (1.11 left this for 2.7).

## Change

- **Colour roles, everywhere.** Green filled = confirm or commit (Generate, Copy blueprint, Import Selected, Save,
  Confirm). Orange = selection and accent (the selected toggle or tab, the focus ring, the "Recommended" and non-AUTO
  enable chips, a text "+ Add" action, a slot's hover and open border). Grey text = cancel (Cancel, Close, Keep
  editing). Yellow with a warning icon and words = a warning (unchanged from 1.14). Red = danger, quiet until hovered
  or focused. Blue = info alerts only.
- **One filled next-step button per state.** A pure function, `nextStepOf`, decides whether Generate, the bar's Copy or
  the Results summary card's Copy is the one filled green button; the others are outlined in neutral grey. A warning
  clock's yellow filled Copy takes the slot of the green one.
- **Shapes.** Title-bar headers on every player-facing card and dialog (a lighter band with the heading, a help
  control and the card's actions); inset slots (darker, bordered, square) for item and filter slots; square chips
  (2px corners); one grey "?" help control that opens a popover on click, used for every help affordance.
- **Configure layout.** Target Output, then one **Build** card whose header carries the List/Diagram toggle and holds
  Machines, Belts and chests, Inserters and Drills as sections. An empty Chests block and an empty Drills block are one
  "+ Add" row each. Advanced stays collapsed. Inserter rows are a grid in which Source and Destination grow, filters show
  the set slots plus one "+", and the delete icon is grey until hovered or focused.
- **Contrast.** A token module, a pure contrast helper and a test that asserts AA for every listed pair, plus the
  theme fixes the measurement found. Full WCAG 2.2 AA for the player-facing views.

## The grammar

### Colour roles

| Role | Colour (MUI palette) | Used for | Not for |
|---|---|---|---|
| **Confirm or commit** | Green, filled, black text (`secondary`, and `success` aliased to the same green) | Generate, Copy blueprint (fresh, no warning), Import Selected, Save (rule modal, inserter dialog footer), Confirm (chest filter popover), "Open build file" confirm in 2.1 | Cancel, navigation, "+ Add", decorative chips. Green also stays the "ok" status colour (the Valid chip, success alerts), never a filled button that is not a confirm |
| **Selection and accent** | Orange (`primary`) | Selected toggle button (filled orange, black text), selected tab, the focus ring, "Recommended" chip, non-AUTO enable chip, text-variant "+ Add" and Undo actions, the border of a slot on hover, focus or while its picker is open, progress bars | Filled action buttons |
| **Warning** | Yellow (`warning`), filled, black text, warning icon, words (1.14) | Changed since validation, below-target Copy, warning alerts | Anything that is not a warning |
| **Danger** | Red (`error`) | Discard, Clear Override, delete icons **on hover or focus**, the Invalid chip, error alerts | An idle delete icon: it is `text.secondary` grey |
| **Cancel and neutral** | Grey text (`text.secondary`, MUI `color="inherit"` on a text or outlined button), border `#9e9e9e` | Cancel, Close, Keep editing, Check only, a demoted Generate, Ko-fi, "Copy" in help popovers | Anything the player is meant to do next |
| **Information** | Blue (`info`) | `severity="info"` alerts only | Buttons, icons, chips, help controls |

### Shapes

| Shape | Rule |
|---|---|
| Panel header | A title bar: `SURFACE.titleBar` band at the top of the card, heading (h2 or h3), then the help control, then the card's actions at the right. The body is the dark `SURFACE.panel`. Dialog titles, accordion summaries and popover headers use the same band |
| Section header | A heading inside a card (h3 or h4): bold text with a 1px rule under it, no fill |
| Inset slot | A 32px square, `SURFACE.inset` fill, 1px `#9e9e9e` border, 2px radius, a short inner shadow. Holds an item icon, or a "+" in `text.secondary`. Orange border on hover, focus or while its picker is open. Auto-assigned: dashed border and the word AUTO at 11px |
| Chips | 2px corners (`MuiChip` override), 24px high (`size="small"`) |
| Help control | One grey outlined "?" icon button (`HelpOutline`, `text.secondary`, 30px), `aria-label="About <topic>"`, `aria-haspopup="dialog"`, opens a popover on click, Enter or Space; Esc closes it and returns focus |
| Buttons | Square (`shape.borderRadius: 0`, unchanged). One filled green button per state |

### One filled next-step button per state (C3)

Pure rule, `utils/nextStep.ts`. "Filled" means the green `contained` button (or the yellow `contained` warning Copy,
which takes the same slot). Everything else in the bar is `outlined` with `color="inherit"` (grey border) or `text`.
This table assumes 2.3 has merged (Generate runs the check first, so there is no Validate step; "Check only" is the
secondary action). If 2.7 has to start before 2.3, see Risks.

| State | Filled | Everything else |
|---|---|---|
| The build has problems (1.4's list is not empty) | Generate, **disabled** (grey, with the first problem as visible text beside it, 1.4) | Check only |
| Generating | Generate, disabled, "Generating..." with a spinner | Check only disabled |
| Never generated, build fine | Generate (green) | Check only |
| Fresh results (the build has not changed since Generate), no warning | **Copy blueprint (green)**, in the bar on Configure; on Results the filled one is the summary card's Copy if 2.5's card is mounted, and the bar's Copy is outlined grey | Generate becomes outlined grey, Check only text |
| Fresh results, clock warns (1.14: below target, no recovery, deadlock risk) | **Copy blueprint (yellow, warning icon, words)**; the green is not used | Generate outlined grey |
| Fresh results, just copied | The same button reads "Copied" with a check for 2 seconds; it keeps its colour (green or yellow) | |
| **Stale** results (the build changed, 1.1) | **Generate (green)**: re-running is the next step | "Copy old clock..." stays **outlined yellow** with the warning icon (1.14 veto), never filled |

Signature (exact, so the test and both callers agree):

```ts
export type NextStep = 'generate' | 'copy-bar' | 'copy-page';
export interface NextStepInput {
    problemCount: number;        // problemsOf(...).length from utils/firstProblem.ts (1.4)
    isRunning: boolean;
    hasBlueprint: boolean;       // blueprintString !== null
    stale: boolean;              // 1.1's isStale
    view: 'configure' | 'results';
    pageHasCopy: boolean;        // 2.5's summary card (with its own Copy) is mounted
}
export function nextStepOf(input: NextStepInput): NextStep;
```

Rules, first match wins: `isRunning` returns `'generate'`; `problemCount > 0` returns `'generate'`;
`hasBlueprint && !stale` returns `'copy-page'` when `view === 'results' && pageHasCopy`, else `'copy-bar'`; anything else
returns `'generate'`. The bar and the summary card read the result: a button is filled only when it is the named one.
The warning colour is chosen by 1.14's existing `warns` test, not here.

### PR A: tokens and components

**New**

1. **`theme/tokens.ts`**: `SURFACE`, `ROLE`, `TEXT`, `CONTROL` and `TOKEN_PAIRS` as above. `TokenPair` is
   `{ name: string; fg: string; bg: string; kind: 'text' | 'nonText'; note?: string }`; `fg` may be `rgba(...)`.
2. **`theme/contrast.ts`**: pure, no MUI. Exports `parseColor(input)` (`#rgb`, `#rrggbb`, `rgb()`, `rgba()`; throws on

## Risks and checkpoints

- **No formal checkpoint is tripped.** No new dependency, no CI, release or `.claude` change, nothing the plan contradicts.
  Things the orchestrator should look at for the record (any can be vetoed):

     dialogs and menus from `#474747` and `#3d3d3d` to `#232323`. It is what makes every pair exact and it fits "inset
     slots, title bars", but it is a visible change on every screen. The UX auditor should compare against the review shots.
