Line numbers are for `clock-generator-ui/src` in the working tree of `feat/ux-rework-p1` when this was drafted (0.9.0 code; 1.1,
1.2 and 1.8 are specced but not merged). **1.11 runs late in the phase.** Before starting, re-find every spot below by the

Owner decision this serves ("Accessibility"): **full WCAG 2.2 AA for player-facing views; the developer timelines (State
Transition Timeline, Transfer Activity Timeline, Debug) get light fixes only.** "Light" here means: heading level, button names,
focus ring and target size. Hover-only chart content (C2, C11, C12, C17) is 2.10's job and is not touched.

## How it is wrong today (checked in source; the implementer re-checks with the "before" run of `capture-a11y.mjs`)

- **C8, unnamed controls.** The dnd-kit drag handle (`SortableList.tsx:110-124`) spreads `attributes` (`role="button"`,
  `tabIndex=0`) and has no label. Delete `IconButton`s in every row, the filter-slot remove `×`, the lane delete, the blueprint
  copy icon and two fullscreen close buttons have only an icon. Every MUI `Select` has an `<InputLabel>` that is not tied to it
  (no `labelId`), so the combobox has no name. The clock `Radio`s have no label and no `name`.
- **C9, tooltips that overwrite names.** `Tooltip` with a string `title` sets `aria-label={title}` on its child
  (`node_modules/@mui/material/Tooltip/Tooltip.js:545-551`). Where the child already has text, the paragraph replaces the name:
  the Belt and Wake-ups column headers, the Status chip, the LCM chips and toggle, the Copy blueprint button when a rate
  warning exists, the Machine Facts chips (a heading reads "22.96874920527133/s"), the Strategy options.
- **C10, hover-only help.** `ClockAlternativesPanel.tsx:159-170` is a bare `InfoOutlined` SVG with an `aria-label`. MUI
  `SvgIcon` is `aria-hidden` unless it has `titleAccess`, so it has no name, no focus and no touch path.
- **C13, nothing is announced.** No `role="status"`. Generation progress is an unnamed `LinearProgress`
  (`BlueprintOutput.tsx:87`).
- **C22, flat headings.** The title is a `div` (`App.tsx:289`). Every section title is `Typography variant="h6"`, which renders
  `<h6>`. Accordion titles (`TransferPlanPanel.tsx:59`, `OverridesForm.tsx:34`, `DebugPanel.tsx:69`) put an `<h6>` inside
  MUI's own `<h3>` wrapper. `subtitle1` and `subtitle2` also map to `<h6>` in MUI (`Typography.js:128-129`), so every label
  such as "Latched Mode" is an `h6` too.
- **C25, focus and targets.** The filter-slot remove `×` is 16x16 (`FilterSlotSelector.tsx:150-174`, `ChestFilterSlotSelector.tsx:164-188`)
  and is a `<button>` nested in a `role="button"` (a nested-interactive ARIA error; the outer `aria-label` also hides the inner
  button's name). Both slot selectors set `outline: 'none'` on `:hover, :focus`
  (`FilterSlotSelector.tsx:116`, `ChestFilterSlotSelector.tsx:130, 225`) and their `:focus-visible` rule uses `boxShadowColor`,
  which is not a CSS property, so the ring is `currentColor`. The "AUTO" badge is 8px (`FilterSlotSelector.tsx:138`). The drag handle
  is 20x20.
- **Found while auditing, same cause, same fix** (not in the C8 list but inside "WCAG 2.2 AA for everything this touches"):
  dnd-kit's default announcements read the item's UUID; the sticky header and footer can cover a focused field (2.4.11 Focus Not
  Obscured); there is no `<main>`; the results tabs have no `tabpanel`s; the ⋮ menu has no `aria-haspopup`.

## Change

- **Every control has a name.** A screen reader or voice control user hears "Reorder inserter 2", "Delete inserter 2", "Remove
  filter 1: iron-plate", "Machine type", "Belt strategy", "Copy blueprint string", "Close fullscreen". Each row is a named group
  ("Inserter 2"). The clock radios are named by their clock and share a `name`, so arrow keys move between them.
- **Tooltips describe, they do not rename.** `describeChild` on every tooltip whose child already has text. The text moves to
  the accessible description. Elements that are only a tooltip target get `tabIndex={0}` so the tooltip opens on keyboard focus.
- **The (i) next to a clock is a button.** Tab reaches it, Enter or Space opens a popover with how the clock is made (and its
  status), Esc closes it and returns focus. Touch works.
- **A heading outline.** One `h1` (the title), `h2` for every section (Configure and Results), `h3` for cards inside a
  section. No `h6` is left. Accordion titles are headings of the right level with a `span` inside.
- **One announcements region in the workflow bar.** "Checking the configuration", "The configuration is valid", "Generating
  clocks", "Finished generating. Selected clock: ...", "Blueprint copied". Generation progress is a named progress bar.
- **A visible 2px focus ring everywhere** (theme level, the brand orange, with a 2px gap), no `outline: none` left on a
  focusable control, and the sticky header and footer never cover the focused control.
- **Every interactive target is at least 24x24 CSS px**: the drag handle, the filter `×`, and anything else the capture script's
  size audit finds.

### `WorkflowBar.tsx` (A)

The workflow bar owns the announcements. **One `role="status"` region is ours.** dnd-kit renders its own
`role="status" aria-live="assertive"` node per `DndContext` (5 lists) and React Flow its own `aria-live` node; leave those, they
announce drags and diagram keyboard moves. The capture script therefore counts regions **inside the header only**.

- **Region.** First child of the root: `<Box role="status" sx={visuallyHidden}>{announcement}</Box>`, mounted for the whole life of
  the bar (a live region must exist before its text changes). `role="status"` implies `aria-live="polite"` and `aria-atomic="true"`.
- **What is announced** (strings are the exported constant `ANNOUNCEMENTS` in `workflowAnnouncement.ts`, one place for 1.12):

  | Event | Text |
  |---|---|
  | check starts (`validationStatus` becomes `running`) | "Checking the configuration." |
  | check ends valid | "The configuration is valid." |
  | check ends invalid | "The configuration is not valid." (1.4's first-problem message is shown in text elsewhere; do not repeat it) |
  | becomes out of date | "The configuration changed since it was checked." |
  | generation starts (`isLoading` false to true) | "Generating clocks." |
  | generation ends with a blueprint (`isLoading` true to false and `blueprintString` set) | "Finished generating. Selected clock: {selectedLabel}." |
  | generation ends without a blueprint (error, or 1.1's `clearResults` dropped it) | nothing (the error `Alert` is `role="alert"`; a cleared run is not news) |
  | blueprint copied | "Blueprint copied." |

  Progress ("3 of 8") is **not** announced per update: that is dozens of interruptions. The progress bar below has a name and a
  value; a player can inspect it.
- **`workflowAnnouncement.ts` is pure.** `interface WorkflowSnapshot { validationStatus: 'none'|'running'|'valid'|'invalid'|'out-of-date'; isLoading: boolean; hasBlueprint: boolean; selectedLabel: string | null }`
  and `workflowAnnouncement(prev, next): string | null`. Generation transitions are checked before validation transitions; at most
  one message per call.
- **How it is wired.** `react-hooks` (recommended preset, `eslint.config.js:15`, plugin 7.0.1 with `set-state-in-effect`) forbids `setState` inside an effect. Use the
  compare-during-render pattern `SortableList.tsx:39-51` uses: keep `prevSnapshot` in state, compute
  `workflowAnnouncement(prevSnapshot, snapshot)` while rendering, and when it returns text call `setAnnouncement(text)` and
  `setPrevSnapshot(snapshot)`. A `useEffect` that sets a `setTimeout(() => setAnnouncement(''), 5000)` (setState inside the timer
  callback is allowed) clears the text so the same message can be announced twice.
- **Copy.** In `handleCopy` (lines 55-67, or 1.1's `copyBlueprint`), after the clipboard write succeeds, `setAnnouncement(ANNOUNCEMENTS.copied)`.
  **Coexistence with 1.5's snackbars:** the below-target toast ("Copied. {rate warning}") is an `Alert`, which MUI renders with
  `role="alert"`, and 1.5 moves it to an app-root portal. When `rateWarning !== null` the toast already announces the copy, so
  the region says nothing then (`handleCopy` skips the `setAnnouncement` call). If 1.5 changes that toast to something that is not
  an alert, announce "Blueprint copied. {rateWarning}" in the region instead. The region never moves with the snackbars; it
  stays in the bar.
- **Tooltips.** Line 102 (`<Tooltip title={rateWarning ?? ''}>` around Copy blueprint): add `describeChild`, so the warning is
  the button's description and not its name. Line 141 (`<Tooltip title="Validate the configuration first">` around the
  `span` of the Generate button): add `describeChild` (1.4 rewrites this; keep the rule: **any tooltip whose child has its own
  text gets `describeChild`**).
- **Decorative spinner.** Line 150: `<CircularProgress ... aria-hidden />` (the button text says "Generating...").
- **Progress bar.** The `GenerationProgressStatus` named below gets its name from `BlueprintOutput.tsx`.
