# The record

One small JSON file per blast job (`<group>-<name>.json`, the blast's job key): the clock the generator selects for the build and every alternative it
weighed. It is committed and generated by `scripts/blast/blast.sh`, never edited by hand. CI regenerates it and compares it field by field; a
difference fails with a table of job, field, before and after.

It holds what `blast.sh` computes for the job and nothing else: no seconds, no path, no machine. A job is one of the blast's six groups
(`config`, `pickup`, `overhood`, `front`, `blocked`, `containers`): the sample configs as they are and the fixtures.

## Fields (format `clock-record-1`)

A field's name and meaning do not change; a new field or a changed meaning is a new format number (`clock-record-2`) and rewrites every file.

| Field | Meaning |
| --- | --- |
| `format` | `clock-record-1` |
| `job`, `group`, `name` | the blast's job key (`config-ACCUMULATOR_640`), its group and its name |
| `config_sha256` | the hash of the job's config as the blast loads it: it says whether a moved result comes with a moved config |
| `job_results_sha256` | the digest of what belongs to the job and no alternative: why it is not stable, the selected index, the alternatives' ids |
| `selected` | the id of the selected alternative (one of `alternatives`) |
| `selected_windows` | the selected clock's windows: for each inserter or drill, `start-end` pairs in ticks of the period (`0-10,54-64`: the opening edge and the closing edge of each window); empty when the machine has none |
| `alternatives` | every alternative, in the generator's order, one per line |
| `error` | instead of the fields from `job_results_sha256` on, when the config failed to generate: the error |

An alternative:

| Field | Meaning |
| --- | --- |
| `id` | the alternative's id, unique in the job |
| `verdict` | stable, unstable or whatever the generator says of it |
| `holds` | whether the clock holds the target |
| `rate` | items a second it makes |
| `supply` | the belt's kind (`moving` or `backed`), or null |
| `period` | the period in ticks |
| `wake_ups` | inserter wake-ups a minute, to three decimals; null where the clock has none |
| `descriptions_cut` | descriptions Factorio's 500 bytes would cut (0 is the rule) |
| `clock_sha256` | the hash of the exported clock's identity (the blueprint without its text, and the schedule): the hash a game recording is tied to |
| `windows_sha256` | the hash of all this alternative's windows (the selected one's are in `selected_windows`) |
| `text_sha256` | the hash of the exported blueprint with its text, which moves with any description |
| `results_sha256` | the digest of what the clock hash leaves out: label, description, insights, verdict, assessment, the simulation's histories, the clock-only run, the fuel view |

## Regenerating it

```bash
# all six groups, every job (the record covers all 75), then write the files
BLAST_GROUPS=config,pickup,overhood,front,blocked,containers bash scripts/blast/blast.sh run .. <out>
bash scripts/blast/blast.sh record write <out>          # or the cache entry's key, as `blast.sh list` prints it
bash scripts/blast/blast.sh record check <out>          # the table of differences against the committed files; exit 1 on any
```

A run that is cached (the key of the engine and the job list) writes the record in seconds. After a rename of jobs, `record check --map <renames.txt>`
takes the blast's rename map (`old-job-key new-job-key` a line) and compares a renamed job with its new name.

## MOVES.md

A pull request that changes any record file commits the new files and adds an entry to [MOVES.md](MOVES.md) naming each moved job and why.
