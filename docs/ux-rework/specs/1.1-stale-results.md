# 1.1 Never offer a stale blueprint
Findings: A5, B1, C5  ·  Implementer model: opus  ·  Branch: feat/ux-rework-p1-stale-results

Line numbers are for `clock-generator-ui/src` at the head of `feat/ux-rework-p1` (0.9.0 code, unchanged since the review).

## Change
- **The site remembers what each generation was for.** When Generate starts, it records the config key (the
  `JSON.stringify` of `exportConfig()` that `App.tsx` already computes as `configKey`) and the target recipe and rate
  of that config. Results are "stale" when the key of the build on screen differs from the recorded one.
- **A banner across Results while stale:** "These clocks are for {recipe} at {rate}/s. Your build has changed since.
  Generate again." Editing a value and putting it back makes the key equal again, so the banner goes away.
- **Every way to copy the blueprint changes while stale:**
  - The workflow bar's "Copy blueprint" reads "Copy old clock…" (warning colour). Clicking it opens an MUI dialog that
    says what the clock was made for and asks to confirm. Cancel (the focused button) copies nothing.
  - The Blueprint tab's copy icon and its select-and-copy text box are replaced, while stale, by a short note and the
    same "Copy old clock…" button, so the string cannot be copied by hand around the dialog.
- **Import Config, Paste from Factorio and Reset Configuration clear the results and the validation.** The clocks,
  timelines, log, progress, the Validate result (so the old transfer plan goes) and any generation still running are
  dropped. Results shows "Nothing generated yet", the workflow bar has no Copy button and no validation chip.
- **Not changing:** editing the build (a value, a row, a reorder) keeps the results on screen under the banner, and the
  existing "Changed since validation" chip and out-of-date Validation panel stay as they are.

### Every place a blueprint can be copied (the complete list)
`grep -i "blueprint\|clipboard"` over `src` finds exactly two writes of a blueprint string, plus one text box. Nothing
else (Insights, Details, Fuel, Timelines, `ClockAlternativesPanel`) shows or copies it.

| Surface | Where | Today | Stale |
|---|---|---|---|
| Workflow bar button | `WorkflowBar.tsx:55-67` (`handleCopy`), `:102-112` | "Copy blueprint", copies at once | "Copy old clock…", dialog first |
| Blueprint tab copy icon | `BlueprintOutput.tsx:25-35` (`handleCopy`), `:63-74` | copies at once | not rendered; "Copy old clock…" button instead |
| Blueprint tab text box (manual select + Ctrl+C) | `BlueprintOutput.tsx:53-62` | readable and selectable | not rendered while stale |

(`DrillsForm.tsx:72` and `MachinesForm.tsx:56` copy console commands, not blueprints. Out of scope.)

## Acceptance criteria
- [ ] After Generate on a build, editing any form value (A5, shot 27: target 240 to 200) makes the workflow bar's
  button read "Copy old clock…" and a click copies nothing until the dialog's "Copy old clock" is pressed. Cancel and
  Escape leave the clipboard unchanged.
- [ ] While stale, Results shows the banner "These clocks are for {recipe} at {rate}/s. Your build has changed since.
  Generate again." with the generated recipe and rate, not the current ones (C5, B1).
- [ ] Setting the edited value back to what it was removes the banner and restores "Copy blueprint" (the key is equal
  again).
- [ ] The Blueprint tab has no text box and no one-click copy icon while stale; its "Copy old clock…" button opens the
  same dialog (the third place a blueprint can be copied).
- [ ] Import Config of another build (A5, shots 32, 34, 35): the workflow bar loses Copy, Results says "Nothing
  generated yet", the Validation panel is back to its unvalidated state (no old transfer plan, no "Changed since
  validation" chip) (B1).
- [ ] Paste from Factorio with "Import Selected" and at least one box ticked, and Reset Configuration, do the same.
  Cancel on the paste dialog, a failed paste, a failed import and "No items selected" clear nothing.
- [ ] Importing while a generation is running stops showing its progress and clocks; clocks that finish afterwards do
  not appear. Generate works again straight away and shows only the new run.
- [ ] A Validate answer that arrives after Import, Paste or Reset does not repopulate the Validation panel.
- [ ] A fresh generation with no edits since shows no banner and "Copy blueprint" (no false positives), also after
  switching alternatives and after switching Configure/Results.
- [ ] No new dependency; `npm test`, `npm run lint`, `npm run knip`, `npm run check:icons` and `npm run build` pass in
  `clock-generator-ui`.

## Risks and checkpoints
- **No checkpoint is tripped.** No new dependency, no CI, workflow or `.claude` change, nothing the plan contradicts.
  MUI `Dialog` is already used in `App.tsx` and `ConfigImportExport.tsx`.
- **Two small additions beyond the plan's wording, both needed for "Done when":** hiding the Blueprint tab's text
  box while stale (without it the blueprint can be copied by hand with no confirmation), and the dialog's wording (the
  plan only says "asks for confirmation"). The orchestrator can veto either.
- **Plan beats the reviews where they differ:** A5 suggests disabling Copy, C5 suggests dimming the table and the
  label "Copy previous blueprint". The plan chose "Copy old clock…" with a confirmation and a banner, so this spec does
  not disable Copy and does not dim.
- **Copy wording and the glossary (1.12).** The banner sentence and button label are the plan's own, and the dialog
  uses "clock" and "build". If the owner's glossary changes those words, the strings in `utils/resultsStaleness.ts`
  and `StaleCopyDialog.tsx` are the only places to change.
- **A generation still running when Import is pressed.** `clearResults` drops it by clearing `generationRef` (late
  messages are ignored) but cannot stop the worker threads; they finish their current task before taking the next
  Generate's work, so the next run can start slowly after an import mid-generation. Real cancelling belongs to the
  Phase 3 "cancel and keep results" item. If it feels slow in the in-flight screen, report it; do not terminate or
  re-create the worker pool here.
- **Overlap with other Phase 1 items, which merge after this one:** 1.2 moves `WorkflowBar` into the app bar (the
  button/dialog change here is inside the same component), 1.3 snapshots config at the same Import, Paste and Reset
  call sites in `ConfigImportExport.tsx` (it should keep the `onBuildReplaced` call; Undo restores the form, not the
  cleared results), 1.4 changes the Generate tooltip in `WorkflowBar`. Later items that replace a whole build (for
  example "Try an example", 2.1) must call the same `onBuildReplaced`.
- **Stale means "the form differs", not "the outcome would differ".** Reordering rows or touching a field that does
  not change the clock still shows the banner. That errs on the safe side and matches the plan.
- **Persistence.** Results are not saved across reloads, so a reload shows an empty Results view. Nothing to do.
